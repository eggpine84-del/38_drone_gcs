# DB 엔지니어링 표준 마스터 체크리스트 (Database Engineering Master Checklist)

> **원칙**: 소규모 MVP부터 대규모 분산 SaaS까지 전 생애주기 무결성·보안·확장성을 강제하는 표준 규격서.

---

## 1. 기본 5대 표준 파이프라인 (Base Integrity / 100% 필수)

| 영역 | 검증 항목 | 핵심 강제 기준 |
| :--- | :--- | :--- |
| **P1. 스키마 헌법** | [ ] 네이밍 / PK | 복수형 스네이크(`users`, `orders`), 단일 PK `id`(BIGINT / UUID v7) |
| | [ ] 4대 메타 컬럼 | `id`, `created_at`(UTC), `updated_at`(자동갱신), `is_deleted`(Soft Delete 0/1) |
| | [ ] 엔진 제약조건 | `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK` DB 레벨 명시 (앱 검증 의존 금지) |
| **P2. 형상 관리** | [ ] 수동 DDL 금지 | GUI/콘솔 임의 수정 0건, 마이그레이션 도구(Alembic/Flyway/Prisma) Git 버전 추적 |
| | [ ] 롤백 / 무중단 | `upgrade`/`downgrade` 1:1 대칭 검증, 컬럼 변경 시 3단계(추가->이중쓰기->제거) |
| **P3. 아키텍처 격리** | [ ] FCIS 순수 Core | Pure Core(도메인 연산) 내 DB/세션/I/O 호출 0건 보장 |
| | [ ] 저장소 / UoW | 전담 Repository 캡슐화, `with db_transaction():` 다중 쿼리 원자성(ACID/Rollback) |
| | [ ] 쿼리 최적화 | 연관 데이터 N+1 방어 (JOIN 또는 Batch 로딩 필수) |
| **P4. 보안 & 격리** | [ ] SQLi 차단 | 100% 파라미터화 바인딩(`?`, `%s`), 동적 문자열 조립(`f-string`) 영구 금지 |
| | [ ] 권한 최소화 | 런타임 서비스 계정 `DROP TABLE`, `TRUNCATE`, `ALTER TABLE` DDL 권한 박탈 |
| | [ ] 테넌트 격리 | PostgreSQL RLS(Row-Level Security) 강제 / SQLite 물리 격리 + Path Traversal(`..`) 차단 |
| | [ ] 테스트 DB 샌드박스 | 테스트 실행 시 운영 DB 오염 0건 보장 (환경변수 격리 샌드박스 주입 + 단일 팩토리의 운영 연결 차단/강제 전향 + 물리 성역 해시가드) |
| | [ ] 부팅 무터치 헌법 | 기동(lifespan) 시 DB 기 존재 시 DDL 재호출 금지 (Cold-Start 미존재 시에만 1회성 생성, 무터치 보존) |
| | [ ] Supabase 6543 풀러 강제 | 기본 5432 세션 풀러(동시 15개 하드캡) 영구 금지, 반드시 6543 트랜잭션 풀러 바인딩 및 어댑터 자동 승격 의무화 |
| **P5. 보호 & 복구** | [ ] 물리 삭제 금지 | 비즈니스 데이터 `DELETE` 영구 금지 (`is_deleted = 1` 논리 삭제 통일) |
| | [ ] 지속 복제 백업 | SQLite Litestream(WAL 스트리밍) / PostgreSQL PITR(시점 복구 스냅샷) 활성화 |
| | [ ] SQLite 3대 PRAGMA | `foreign_keys = ON`, `journal_mode = WAL`, `busy_timeout = 5000` 커넥션 강제 |

## 2. 스케일업 & 특수 워크로드 확장 가드 (High-Scale / Advanced)

| 상황 (트리거) | 확장 가드 항목 | 적용 기술 및 구현 규칙 |
| :--- | :--- | :--- |
| **동시성/트래픽 폭증** | [ ] 캐싱 계층 | Redis Cache-Aside 패턴 적용 (단순 반복 읽기 DB 인입 차단) |
| | [ ] 읽기/쓰기 분리 | Master(Write) / Replica(Read) 분리 및 CQRS 적용 |
| | [ ] 충돌/경합 방어 | 원자적 업데이트(`UPDATE ... WHERE`), 비관적(`SELECT FOR UPDATE`) / 낙관적(`version`) 락 |
| | [ ] 수평 샤딩 기준 | 기준 키(`tenant_id`/`user_id`) 파티셔닝/샤딩 기준 수립 |
| **빅데이터/로그 통계** | [ ] 운영/분석 분리 | OLTP(운영) 풀스캔/무거운 집계 차단, OLAP(분석) 전용 환경 물리 분리 |
| | [ ] 컬럼 분석 DB | 수억 건 로그는 ClickHouse, BigQuery, Snowflake로 비동기 ETL/ELT 이관 |
| | [ ] 큐 버퍼링 | 대량 이벤트 인입 시 Kafka, RabbitMQ, SQS를 선행 버퍼로 배치 |
| **전문검색/비정형** | [ ] 검색 엔진 분리 | `LIKE '%...%'` 차단, 형태소/역색인은 Elasticsearch/OpenSearch 위임 |
| | [ ] 특수 DB 결합 | 소셜 관계망: Neo4j / AI 임베딩: 벡터 DB(pgvector/Pinecone) / 세션: Redis |

## 3. 아키텍처 진화 트리거 (Level 1 ➔ Level 2)

| 구분 | Level 1: 1인 고속 개발기 (현재 상태) | Level 2: 엔터프라이즈 정석기 (승격 상태) |
| :--- | :--- | :--- |
| **적정 규모** | 1인 개발 / 테이블 20개 이하 / 단일 서버 | 다중 팀원 / 테이블 30개 이상 / 분산 클라우드 |
| **스택 구성** | Raw SQL (`execute_query`) + DDL 1회 멱등 캐싱 + SQLite 하이브리드 | Type-Safe ORM (SQLAlchemy 2.0/SQLModel) + Alembic CLI + 순수 PostgreSQL |
| **장점 vs 부채** | 극강의 속도, 셋업 0 / 오타 런타임 위험, 롤백 불가 | 오타 린트 검출, 무중단 롤백 / 초기 셋업 비용, 보일러플레이트 |

### Level 2 즉시 승격 5대 판정 트리거 (1개 이상 충족 시 전환)
- [ ] **T1 (팀원 확장)**: DB 스키마를 다루는 개발자가 2명 이상으로 증가 (Alembic 필수)
- [ ] **T2 (오타 장애)**: 컬럼명/테이블명 오타로 인한 런타임 에러(`no such column`) 1회 이상 발생 (Type-Safe ORM 필수)
- [ ] **T3 (테이블 규모)**: 비즈니스 테이블 개수 30개 초과
- [ ] **T4 (서버리스 배포)**: Vercel, AWS Lambda 등 무상태(Stateless) 상용 환경 확정 (PostgreSQL 단일화 필수)
- [ ] **T5 (롤백 SLA)**: 배포 실패 시 스키마 즉각 다운그레이드(Downgrade)가 계약상 요구될 때
