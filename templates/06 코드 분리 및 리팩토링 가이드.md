# 06 코드 분리 및 리팩토링 가이드

## 1. 3대 핵심 원칙
- **Working Code First**: 파일 < 300줄(주석 포함), 함수 < 20줄, 단일 책임 유지 시 무조건 Single File 유지.
- **Anti-Premature**: 성급한 디렉토리 분리 및 과도한 조기 추상화 엄단.
- **Zero Logic Change**: 기능 추가/버그 수정과 구조 개선 동시 진행 영구 금지.

## 2. 판정 매트릭스 (2개 이상 충족 시 분리 제안)
- **규모**: 파일 < 300줄(유지) vs 단일 파일 ≥ 300줄(분리 / 280줄 이상 임박 관리).
- **분기**: if-else ≤ 2개(유지) vs if-elif ≥ 3개(분리 / Table-Driven 무순서 Dict 필수).
- **책임**: 단일 책임(유지) vs Pure Core(연산)와 Shell(I/O) 혼재(분리).

## 3. [스케일업] 배치 철칙 (Rule of Three)
- **1단계 (서브모듈 < 3개)**: 조기 분가 절대 금지. 기존 디렉토리 내부(`core/`, `shell/`) 서브모듈/헬퍼로 1차 분리.
- **2단계 (서브모듈 ≥ 3개 누적)**: 도메인 응집도 형성 시만 `features/<도메인>/` 독립 분가 승격.
- **피처 수평 참조 영구 금지**: `features/A` -> `features/B` 직접 import 금지 (이벤트/도메인 인터페이스 통신).
- **Shared 승격 3회 원칙**: 3개 이상 피처에서 완전 동일 중복 시만 `shared/` 승격 (조기 공통화 엄단, 5줄 중복이 결합보다 우위).

## 4. FCIS 분리 공식 & 설정 격리
- **Pure Core (`core/`)**: 비즈니스 계산·상태머신 100% Pure Function (DB/Net/File/Time/Random Side-Effect 0건).
- **I/O Shell (`shell/`)**: DB/API/File/Time 수집 전담 ➔ Core에 Pure Data 주입.
- **설정 격리**: 보안/인프라는 `.env`, 비즈니스 운영/동적 상태는 **100% DB 전담** (정적 json 배제).

## 5. S6 4대 안전 레일
1. **단위 통제**: 1회당 단 1개 모듈(파일/함수)만 분리.
2. **인터페이스 동결**: 분리 전후 I/O 스키마 100% 고정 (외부 호출부 영향 차단).
3. **Zero-Mutation**: 기존 핀테스트 코드 수정 0건 & 100% Green 유지.
4. **Git Clean 선행**: 작업 전 Clean Commit 확인 필수 (즉시 원복 보장).

## 6. 점검 및 보고 프로세스
1. 300줄 초과 모듈 식별 (OS 스캔).
2. 스케일업(3개 기준) 검증 포함 인터페이스 동결 분리 계획 [A/B안] 보고.
3. 사장님 사전 승인 후 `replace_file_content`로 핀포인트 분리.
