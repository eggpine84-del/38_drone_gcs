# 07 소프트웨어 범용 규격화 체크리스트

> 코드 작성 전 4대 게이트 체크리스트 검증 완료 후 구현 착수.

### G1. 입력 규격 (Input Contract)
- [ ] **형태 고정**: `TypedDict` / Pydantic / DTO 필수 (날것 `dict` 금지)
- [ ] **3줄 Guard**: 초입에서 `None`/빈값/비정상값 조기 반환 (Early Return)
- [ ] **불변 보장**: 외부에서 넘어온 원본 객체/리스트 내부 변형(Mutate) 금지

### G2. 로직 규격 (Pure Core)
- [ ] **Side-Effect 0**: 함수 내 I/O, DB, print 금지 (시간/난수는 인자로 주입)
- [ ] **100% 결정론**: 동일 Input에는 언제나 100% 동일 Output 반환
- [ ] **Table-Driven**: 단순 상태 분기 시 `if-elif` 대신 Dict 매핑
- [ ] **단일 책임**: 단일 함수 50줄, 단일 모듈 300줄 초과 시 분리

### G3. 경계 규격 (Boundary / Repository)
- [ ] **인프라 은닉**: 비즈니스 로직에 SQL, HTTP Client, SDK 직접 노출 금지
- [ ] **초고속 Mocking**: 외부 인프라 없이 0.01초 내 Fake 객체로 구동 가능
- [ ] **원장 보호**: 비즈니스 원본 데이터 하드 딜리트(DROP/DELETE) 금지
- [ ] **장애 격리**: 외부 모듈/API 호출 장애 시 Fallback 처리 (크래시 방어)

### G4. 출력 및 테스트 (Result Envelope & Pin-Test)
- [ ] **초고속 핀테스트**: 구현 전 0.01초 Red 선작성 ➔ Green 통과 (정상/예외 검증)
- [ ] **결과 봉투 통일**: `Result[T]` (성공 여부, 데이터, 명시적 에러 코드) 구조 반환
- [ ] **추적 격리**: 시스템 내부 예외(Traceback) 날것 노출 금지, 도메인 에러로 포장
- [ ] **멱등성 보장**: 동일 트랜잭션 키로 재실행 시 데이터 오염 방지

### G5. 아키텍처 가드 (Arch-Test)
- [ ] **기계적 격리 검증**: `ast` 기반 피처 간 수평 import 및 Core 내 I/O import 탐지 시 빌드 즉시 차단 (Red).
