# 애플리케이션 백본 표준 마스터 체크리스트 (Application Backbone Master Checklist)

> **원칙**: 모든 웹/API 프로젝트에서 API 응답, 입력 검증, 설정 관리, 정적 자원의 파편화를 영구 박멸하고 표준 아키텍처를 강제하는 백본 규격서.

---

## 1. 5대 핵심 백본 파이프라인 (Core Backbone Integrity)

| 영역 | 검증 항목 | 핵심 강제 기준 |
| :--- | :--- | :--- |
| **B1. API 응답 헌법 (Response Envelope)** | [ ] 단일 봉투 규격 | 모든 API 응답은 `{"success": bool, "data": Any, "error": dict/null}` 단일 JSON 포맷 준수 |
| | [ ] 성공 규격 | `{"success": true, "data": <결과객체/배열>, "error": null}` |
| | [ ] 실패 규격 | `{"success": false, "data": null, "error": {"code": "ERR_CODE", "message": "사용자 안내 메시지"}}` |
| | [ ] 상태코드 매핑 | 200(성공), 400(입력오류), 401(미인증), 403(인가실패), 404(자원없음), 500(서버장애) 표준 엄수 |
| **B2. 입력 검증 헌법 (DTO / Schema Validation)** | [ ] Schema First | 원시 딕셔너리(`dict.get()`) 파편화 금지, Pydantic 모델 등 선언형 DTO 클래스 강제 |
| | [ ] 자동 살균 차단 | 잘못된 타입, 필수값 누락, 길이 초과 시 비즈니스 함수 진입 전 400 자동 거부 (Fail-Fast) |
| | [ ] 도메인 가드 | 이메일/전화번호 정규식 검증, 금액 음수 차단(`amount <= 0`), XSS 위험 문자 살균 |
| **B3. 설정 및 비즈니스 상태 SSOT 헌법 (Config & State SSOT)** | [ ] 비즈니스 상태 100% DB 전담 | 메뉴 구조, 회사명/테넌트 식별자, 위젯 설정 등 동적 비즈니스 상태 디스크 파일(json/txt/ini) 저장 영구 금지 (상태 오염 원천 차단) |
| | [ ] 인프라 설정 2원화 | 부팅/시스템 옵션(`config/config.ini`) + 보안 비밀키(`.env`) 계층 분리 (.env 환경변수 최우선 덮어쓰기) |
| | [ ] 평문 저장 금지 & 무결성 | DB 접속 암호, JWT 시크릿, API 키 소스코드 하드코딩 0건 및 기동 시 필수 환경변수 전수 검사 |
| | [ ] 부팅 수명주기 무터치 | 서버 기동(lifespan) 시 기 존재하는 운영 DB를 향한 불필요한 DDL/트랜잭션 실행 0건 보장 |
| **B4. 정적 자원 헌법 (Static Separation)** | [ ] 문자열 코드 금지 | 백엔드 파일(Python 등) 내부의 거대 인라인 JS/CSS 문자열(`"""`) 영구 금지 |
| | [ ] 물리 파일 분리 | 자바스크립트는 `static/js/*.js`, 스타일은 `static/css/*.css` 순수 정적 파일로 격리 |
| | [ ] 린트 및 캐싱 | 프론트엔드 코드 IDE 문법 검사(ESLint/Stylelint) 활성화 및 브라우저 캐싱(ETag/304) 보장 |
| **B5. 추적 및 비동기 헌법 (Trace & Async Worker)** | [ ] 추적 관측성 (Trace ID) | 인입 즉시 1회용 `x-trace-id` 발급 및 전 구간 로그/응답 헤더 전파 바인딩 |
| | [ ] 비동기 위임 (Worker) | I/O 1초 초과 외부 연동(메일/알림/블록체인)은 API 본선 즉시 반환 후 Background Worker 위임 |

## 2. API 응답 단일 봉투 (Response Envelope) 레퍼런스

```json
// [성공 표준]
{
  "success": true,
  "data": {
    "user_id": "u_1001",
    "email": "user@example.com",
    "role": "OWNER"
  },
  "error": null
}

// [실패 표준]
{
  "success": false,
  "data": null,
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "아이디 또는 비밀번호가 일치하지 않습니다."
  }
}
```

## 3. 백본 성숙도 진화 가이드 (Level 1 ➔ Level 2)

| 구분 | Level 1: 1인 고속 개발기 (초기 린 스타트) | Level 2: 엔터프라이즈 정석기 (서비스 상용 확장) |
| :--- | :--- | :--- |
| **API 프레임워크** | 경량 웹 라우터 / 단일 진입점 dispatch | FastAPI / NestJS 등 완전한 스키마 기반 프레임워크 |
| **입력 검증** | Core 모듈의 dataclass / TypedDict 수동 검증 | Pydantic v2 / Zod 스키마 자동 역직렬화 & Swagger 연동 |
| **설정 관리** | `.env` 단일 통제 + 중앙 `config_loader` | Pydantic BaseSettings + AWS Secrets Manager / Vault |
| **정적 자원** | 정적 파일 서빙 디렉토리 분리 (`static/`) | Vite / Webpack 번들러 기반 빌드 및 CDN(S3/CloudFront) 배포 |

### Level 2 승격 4대 판정 트리거
- [ ] **트리거 1**: 프론트-백엔드 간 API 파라미터 오타/타입 불일치로 인한 장애가 1회 이상 발생했을 때
- [ ] **트리거 2**: Swagger/OpenAPI 등 외부 연동이나 협업을 위한 자동 문서화가 필요할 때
- [ ] **트리거 3**: 프론트엔드 자바스크립트 코드량이 1,000줄을 초과하여 컴포넌트 단위 빌드가 필요할 때
- [ ] **트리거 4**: 다중 개발 환경(Dev / Staging / Prod)별 환경변수 보안 통제가 분리되어야 할 때

## 4. 빅테크 5대 인프라 격리 관문 (Enterprise External Gateways)
> **원칙**: 비즈니스 로직(Core)에 섞지 않고 시스템 외곽으로 100% 분리·위임하는 5대 전문 센터.

| 관문 (비유) | 실무 시스템 | 비즈니스 로직 분리 역할 (100% 격리) |
| :--- | :--- | :--- |
| **1. 방어 (성문 문지기)** | Kong, API Gateway | 서비스 단일 입구에서 악성 차단·테넌트 식별·단일 관문 라우팅 전담 |
| **2. 관측 (CCTV 관제탑)** | Sentry, Datadog | 코드 내 print 전면 배제, 전 서버 에러·로그·메트릭 중앙 실시간 감시 |
| **3. 금고 (중앙 보안 금고)**| Vault, AWS Secrets | DB암호/API키/설정 파일 분산 금지, 암호화된 중앙 금고 단일 보관 |
| **4. 출입증 (통합 인증소)**| Keycloak, Okta SSO | 개별 로그인 로직 중복 금지, 중앙 세션·토큰 단일 발급 및 회수 |
| **5. 우체국 (비동기 큐)**   | Kafka, RabbitMQ | 알림·대량 정산 등 지연 I/O를 로직과 섞지 않고 메시지 큐 비동기 처리 |
