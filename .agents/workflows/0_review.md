> **원칙**: 감상평 및 칭찬 절대 금지. 코드 수정 절대 금지(Read-Only). 오직 팩트 기반 대조 표만 출력.
1. [대상 자동 판별 및 수집]:
   - 터미널에서 `git status --porcelain` 실행.
   - 변경 사항이 전혀 없으면: "검사할 변경 내역이 없습니다." 출력 후 즉시 종료.
   - 파일 상태에 따라 자동으로 검사 범위를 분기:
     * **새로 만든 파일(`??`)**: 기능 추가로 판정 ➔ 해당 파일의 진입점(Form/API)부터 Core, DB까지 데이터 흐름 전체를 추적.
     * **수정된 파일(`M`)**: 코드 수리로 판정 ➔ `git diff`로 바뀐 라인을 특정하고, 그 라인이 맞닿은 상대 모듈의 입출력 전선을 추적.
2. [4대 급소 교차 대조]:
   - **키 불일치 (Wiring Mismatch)**: 데이터를 보내는 쪽(Caller)과 받는 쪽(Callee)의 Dict 키 및 변수명 철자 1:1 대조.
   - **침묵 기본값 (Silent Fallback)**: `.get(..., default)` 또는 `except: pass`로 인해 오류가 나야 할 상황에 조용히 0, None, 기본값으로 넘어가며 데이터가 유실되는 곳 색출.
   - **가짜 땜질 코드 (Mock Smuggling)**: 빈칸이나 비정상 입력이 들어왔을 때 임의의 정상값으로 채워 넣어 검증을 무력화하는 분기(`if not x: x = y`) 색출.
   - **무늬만 테스트 (Fake Assertion)**: 변경된 기능의 테스트 코드가 `200 OK`만 확인하고, 실제 계산된 데이터(Payload 전체)를 대조하지 않는 가짜 단언 색출.
3. [결과 보고 서식]:
   - 미사여구 일절 없이, 첫 줄에 검사한 파일 목록 요약 후 오직 아래 마크다운 표만 출력:
   
   검사 대상: [신규/수정 파일 N개 목록]
   | 위험도 (High/Med) | 위치 (파일명:라인) | 결함 유형 | 발견 내용 (호출부 vs 수신부 대조 팩트) |
   | :--- | :--- | :--- | :--- |
   | High | dashboard_routes.py:102 | 키 불일치 | 라우터는 'tx_date' 전송 vs Core는 'date' 요구 |
   *(결함이 0건일 경우: "발견된 4대 급소 결함 0건 (정상)" 1줄만 출력)*
4. [명령 대기]:
   - 일체의 코드를 임의로 수정하지 말고, 사용자 지시가 있을 때까지 보고서 출력 후 즉시 멈춘다.
