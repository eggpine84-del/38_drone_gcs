## 1. 릴리즈 개요
본 릴리즈는 AI 코딩 에이전트의 코드 날림, 사각지대 침투, 덮어쓰기 파괴, 그리고 터미널 블로킹을 기계적으로 원천 차단하는 **9대 방탄 훅 시스템의 제2차 정밀 고도화 버전**입니다.

---

## 2. 5대 핵심 업그레이드 내역

### ① `change`(기능 변경) 모드 사각지대 영구 해소
- **기존 문제**: 기존 코드에서 `change` 모드 시 `analyze_git_diff`가 최상단에서 무조건 `allow`로 조기 반환되어 식별자 누락 및 날림 주석 감찰이 우회되는 사각지대 존재.
- **개선 내용**: 
  - 조기 반환 프리패스를 영구 제거.
  - 성우 및 고유 식별자(`id`, `key`, `name`, `code`) 순감소 감찰 100% 강제.
  - 축약 날림 주석(`// 기존 코드 동일`, `...`, `TODO`) 감찰 100% 강제.

### ② `fix`(버그 수정) 모드 70줄 삭제 제한 규칙 및 `change` 15줄 신규 모듈 강제 연동
- **기존 문제**: 버그 수정을 명목으로 AI가 기존 코드를 수십~수백 줄 지우고 임의 재작성하는 위험과, 반대로 15줄 제한 시 UI/HTML 폼 덩어리(50~65줄)를 못 지워 누더기 땜질을 하는 문제 공존.
- **개선 내용**: 
  - `fix` 모드는 실측 팩트(대형 UI 폼/모달 50~65줄)를 완벽 커버하고 100줄 이상 거대 함수 날림을 차단하는 **70줄 삭제 제한** 적용.
  - `change` 모드는 **15줄 제한**을 엄격 적용하여 15줄 초과 개편 시 반드시 **신규 모듈(`v2`) 추가 강제**.

### ③ Win32 커널 파이프(`PeekNamedPipe`) 무중단 stdin 엔진 장착
- **기존 문제**: Windows 서브프로세스/파이프 환경에서 `sys.stdin.isatty()`가 `False`로 판정되나 데이터가 0바이트일 때 `sys.stdin.read()`가 EOF를 무한 대기하여 터미널이 멈추는 현상 발생.
- **개선 내용**:
  - `ctypes.windll.kernel32.PeekNamedPipe`를 이용해 버퍼 대기 바이트가 0일 때 `read()` 호출을 아예 스킵하고 즉시 기본값 반환.
  - `test_gate.py`, `pre_tool_guard.py`, `post_tool_guard.py` 3대 수문장 전원에 공통 적용 완료 (블로킹 0초 컷).

### ④ 턴 종료 최종 무결성 게이트(Stop) 5중 체이닝 확립
1. **스마트 패스**: 문서/이미지 등 순수 비코드 변경 시 0초 즉시 통과.
2. **테스트 불변 가드**: `tests/` 코드의 삭제/약화 단 1줄이라도 감지 시 종료 차단.
3. **전체 회귀 테스트 완주**: `pytest` 318개 전체 자동 실행 및 100% Green 검증.
4. **Git Diff 무결성 가드**: 15줄 삭제, 주석 축약, 식별자 유실 감찰 체이닝.
5. **300줄 한도 감찰**: `src/` 내 파이썬 모듈 300줄 초과 감지 시 리팩토링 파이프라인 강제 회귀.

### ⑤ 훅 전체 흐름도 및 매트릭스 문서 최신화
- [docs/훅 전체흐름도.md](docs/훅%20전체흐름도.md)에 직관적인 5단계 파이프라인 실제 작동 요약표([표 1]) 및 4대 작업 유형별 최종 감찰 룰 매트릭스 표([표 2]) 압축 동기화.
