### 작업 유형별 Diff 및 불변 검증 룰 매트릭스

| 작업 유형               | 핵심 목적         | 테스트 파일 Diff / 불변                      | 명사/데이터 Diff (`src/data/*`)        | 동사/로직 Diff (`src/verbs/*`)            |
| ------------------- | ------------- | --------------------------------------- | --------------------------------- | ------------------------------------- |
| **기능 추가** (Feature) | 없던 기능을 새로 얹음  | **신규 추가만 허용** (기존 테스트 파일 변조 불가)      | **원칙적 금지** (신규 데이터 키 추가만 허용)      | **추가(`+`) 중심** (기존 함수의 대량 삭제 발생 시 차단) |
| **기능 변경** (Change)  | 기획/요구사항이 바뀜   | **수정 허용** (바뀐 스펙에 맞게 테스트 수정)            | **수정 허용** (단, 변경 전후 키 개수/무결성 검사)  | **수정 및 삭제 허용** (자유롭게 변경 가능)           |
| **디버그** (Fix)       | 오작동을 정상화함     | **신규 회귀 테스트 추가만 허용** (기존 테스트 완화/삭제 불가)  | **절대 금지 (O(1) 해시 불변)** (데이터 조작 차단) | **로직 수정 허용** (인터페이스 시그니처 변경 금지)       |
| **리팩토링** (Refactor) | 동작 유지하며 구조 개선 | **절대 금지 (O(1) 해시 불변)** (단 1비트도 변경 불가) | **절대 금지 (O(1) 해시 불변)** (데이터 구조 보존) | **자유로운 수정/삭제 허용** (불변 테스트가 안전망 역할)    |

### O(1) 해시 가드가 잡아내는 3대 급소 무결성 패턴 (Hash Guard)

**1. 성역화 파일(.agents/) 탈옥 변조 감지 (4대 모드 공통)**
- `.agents/guard_config.json`, `hooks.json`, `scripts/` 파일이 세션 시작 대비 1비트라도 바뀌면 즉시 차단.
- AI가 쉘 명령어(`run_command`)나 스크립트로 관제 설정을 끄거나 훅을 무력화하려는 자가 탈옥을 100% 원천 봉쇄.
- (스마트 싱크): 사장님이 직접 훅 수정/복붙 후 이미 Git 커밋 완료(Clean)된 상태라면 합법적 변경으로 자동 인정하여 오탐 방지.

**2. 리팩토링(Refactor) Zero-Mutation 불변 보장**
- `refactor` 모드 중 `tests/` 및 `src/data/` 디렉터리 내 파일의 해시 대조.
- 테스트 코드를 1글자라도 완화/삭제하여 통과시키려는 사기 행위를 0.001초 만에 적발.

**3. 디버그(Fix) 데이터 조작 버그 은폐 차단**
- `fix` 모드 중 `src/data/` 디렉터리 내 파일의 해시 대조.
- 결함을 제대로 수리하지 않고 목업/JSON 데이터를 변조하여 테스트를 통과시키는 행위 차단.

### Git Diff 훅이 잡아내야 할 3대 핵심 유실 패턴 (Diff Guard)

**1. 식별자(ID) 증발 감지 (성우 데이터 누락 방지)**

- 명사/데이터 파일 변경 시, `git diff`의 삭제 라인(`-`)에서 `id:`, `key:`, `name:` 등 고유 식별자가 감지되면 즉시 에러 발생.
- _규칙:_ 기존 데이터 20개에서 1개가 빠져 19개가 되면 무조건 커밋 차단.

**2. 작업 모드별 대량 삭제 차단**

- 작업 모드가 `feat`인데 기존 로직 파일에서 15줄 이상의 연속 삭제(`-`)가 감지되면 AI의 코드 날림으로 판정하고 차단.
- 작업 모드가 `fix`인데 70줄 이상의 연속 삭제가 감지되면 핀포인트 수리 위반으로 판정.

**3. 주석 축약 차단**

- 추가된 코드(`+`) 라인 중에 `// 기존 코드 동일`, `// ...`, `# 기존 코드 동일`, `# ...`, `TODO: implement later` 등의 축약 날림 표현이 포함되어 있으면 즉시 중단.
