# [실행 방법]: 사장님이 "LEGACY_REPAIR.md 읽고 심폐소생해라" 한마디만 입력하면 AI가 아래 절차를 100% 자동으로 완수한다.

## 1. AI 행동 강령 (절대 원칙)

본 문서를 호출받은 AI 에이전트는 **기존 비즈니스 코드를 단 한 줄도 먼저 수정하지 않는다.**
"코드가 너무 복잡하니 처음부터 새로 짭시다(빅뱅 재개발)"라는 변명을 일체 금지하며, 아래의 **[선-테스트 박제, 후-슬라이싱 리팩토링] 5단계 공학적 프로토콜**만을 순서대로 자율 실행한다.

---

## 2. 레거시 심폐소생 5단계 자동 실행 절차

### [0단계]: 대규모 시스템(파일 100~1,000개) 사전 자율 진단 및 도메인 판정 (Triage & Boundary)
1. **전수 스캔 및 위험도 계량화**:
   - 프로젝트 내 전체 파일 개수와 확장자별 파일 수, 총 라인 수를 기계적으로 스캔한다.
   - 300줄 초과 메가 파일 목록(파일명, 라인 수, 파일 내 클래스/함수 개수)을 내림차순 정렬하여 상위 TOP 10을 도출한다.
2. **교살자 패턴(Strangler Fig) 기반 도메인 분할**:
   - 시스템 전체를 한 번에 다루지 않고, 파일들의 디렉터리 경로 및 의존성 관계를 분석하여 독립 가능한 3~5개 서브 도메인(예: Auth/인증, Billing/결제, Presentation/화면, Batch/배치 등)으로 영역을 가상 분할한다.
3. **심폐소생 1호 타겟 도메인 자율 판정 및 사장님 보고**:
   - 아래 3대 기준을 합산하여 **'가장 먼저 심폐소생할 최우선 1개 도메인(파일 20~50개 규모)'**을 AI가 스스로 판정한다:
     - ① 수정 빈도가 가장 높은 핵심 비즈니스 영역인가?
     - ② 하드코딩과 300줄 초과 파일이 가장 심각하게 집중되어 있는가?
     - ③ 외부 의존성이 상대적으로 적어 독립 격리 및 안전망 테스트 작성이 용이한가?
   - 판정 근거와 함께 사장님께 [심폐소생 타겟 도메인 A안 vs B안]을 선제안 보고하고, **사장님의 승인 획득 시에만 1단계로 진입**한다.

### [1단계]: 방탄 통제 인프라 즉시 이식 (안전벨트 체결)
1. 타 프로젝트에서 검증된 감찰관 인프라 세트를 대상 프로젝트 루트에 즉시 복사 및 세팅한다:
   - `.agents/` : `pre_tool_guard.py`, `post_tool_guard.py`, `universal_red_guard.py`, `test_gate.py`
   - `.agents/guard_config.json` : `require_pin_test_first`, `block_direct_overwrite`, `prevent_test_deletion` 강제
   - `AGENTS.md` : Pinpoint Edit, Zero Deletion, TDD 7번 규칙 헌법 주입
   - `templates/` : `00 FCIS.md`, `03 디버그 템플릿.md`, `06 코드 분리 및 리팩토링 가이드.canvas`
2. **효과**: AI가 레거시 코드를 임의로 압축하거나 삭제하지 못하도록 시스템 레벨의 물리적 족쇄를 먼저 채운다.

### [2단계]: 블랙박스 캐릭터라이제이션 핀-테스트 선배치 (동작 박제)
1. **기존 소스 코드는 단 1글자도 수정하지 않는다.**
2. 메가 파일(2,000~3,000줄)의 내부 구현을 파헤치려 하지 말고, **시스템의 최외곽 진입점(API 엔드포인트, CLI 진입점, 메인 실행 함수)**을 식별한다.
3. 현재 시스템에 대표 입력값을 넣었을 때 나오는 실제 출력값을 그대로 단언(Assert)하는 **'블랙박스 캐릭터라이제이션 테스트(Characterization Test)'**를 `tests/`에 작성한다:
   - 정상 케이스 대표 2~3개
   - 극단값/경계값(Null, 빈 문자열, 0) 케이스 1~2개
4. 테스트 러너를 실행하여 **해당 핀-테스트가 100% Pass(Green)됨을 기계적으로 증빙**한다.
   - 코드를 건드리지 않았으므로 반드시 초록불이 떠야 하며, 이것이 향후 리팩토링의 절대 안전망이 된다.

### [3단계]: 06 가이드 기반 점진적 껍질 벗기기 (Interface Freeze 슬라이싱)
1. `templates/06 코드 분리 및 리팩토링 가이드` 원칙을 가동한다.
2. 한 번에 파일 전체를 갈아엎지 않고, **파일당 딱 1개 함수(또는 1개 클래스)**만 타겟으로 지정한다.
3. 타겟 함수의 **입력(Input)과 출력(Output) 스키마를 동결(`Interface Freeze`)**한다.
4. 비즈니스 로직(Core)에서 하드코딩된 설정값(API 키, 경로, 매직넘버)을 먼저 추출하여 `.env` 또는 `config.json`으로 격리한다.
5. 300줄 초과 메가 파일에서 해당 함수를 전용 서브 모듈로 추출(Extract Function/Module)한다.
   - 단, 로직 변경은 0%여야 함 (Zero Logic Change).

### [4단계]: 1:1 불변 증빙 및 점진적 FCIS 순수코어화
1. 모듈 추출 완료 즉시 2단계에서 만들어둔 핀-테스트 및 전체 테스트를 재실행한다:
   - Python: `pytest -q`
   - Node.js: `npm test`
2. **테스트 결과가 이전과 100% 동일하게 초록불(Green)을 유지하는지 증빙**한다.
3. 1회당 1개 모듈 분리가 완료될 때마다 즉시 로컬 Git 커밋을 기록한다:
   - 커밋 메시지 형식: `[Refactor] {모듈명} 메가파일에서 SRP 분리 및 1:1 불변 증빙`
4. 추출된 모듈 내부의 순수 비즈니스 연산은 점진적으로 `core/` 순수 함수(Pure Functional Core)로 승격시킨다.

## 3. 레거시 심폐소생 4대 금기 사항 (Anti-Patterns)

1. **빅뱅 재작성 금지 (Zero Rewrite)**:
   - "코드가 너무 더러워서 새로 짜는 게 빠릅니다"는 핑계를 엄단한다. 레거시의 진짜 가치는 수많은 엣지 케이스와 버그 픽스가 누적되어 있다는 점에 있다. 반드시 제자리 점진 분해(In-place Strangler Pattern)로 해결한다.
2. **테스트 없는 리팩토링 금지 (No Test, No Edit)**:
   - 캐릭터라이제이션 핀-테스트가 1개도 없는 모듈은 단 1줄도 손대지 않는다.
3. **기능 추가와 구조 개선 동시 진행 금지 (Separation of Concerns)**:
   - "리팩토링하는 김에 이것도 고치자"는 순간 지옥이 열린다. 리팩토링(구조 개선) 커밋과 기능 수정(로직 변경) 커밋은 엄격히 분리한다.
4. **의존성 라이브러리 맹목적 최신화 금지 (Dependency Pinning)**:
   - 레거시 시스템의 패키지/라이브러리 버전을 함부로 `@latest`로 올리지 않는다. 동작 무결성이 확보될 때까지 기존 버전을 철저히 고정(Pin)한다.

## 4. [특약]: 버그가 동반된 레거시의 '선-디버깅 후-리팩토링' 3원칙

대상 모듈에 런타임 에러, 예외 발생, 데이터 오염 등 미해결 버그/사이드 이펙트가 존재하는 경우, **300줄 슬라이싱(리팩토링)으로 바로 진입하는 행위를 절대 금지**하며 아래 3단계를 의무 적용한다:

1. **버그 방치 상태의 리팩토링 절대 착수 금지**:
   - 버그가 있는 상태에서 리팩토링을 진행하면 "버그 동작을 예쁘게 모듈화"하거나, "기존 버그와 리팩토링 부수효과가 뒤섞여 원인 규명 불능(Chaos)"에 빠진다.
2. **버그 재현 핀-테스트 선작성 (Pinning Red)**:
   - 전체 코드를 뜯어고치지 않고, 버그가 터지는 입력 조건과 비정상 동작을 기계적으로 증빙하는 테스트를 딱 1개 먼저 작성한다 (AssertionError / Red 실패 확인).
3. **국소 핀포인트 땜질 수리 (Green) ➔ 완전 정상화 후 리팩토링 승격**:
   - 아키텍처나 구조를 바꾸지 말고, 결함 지점만 2~3줄 외과수술식으로 방어하여 테스트를 100% 초록불(Green)로 만든다.
   - 시스템이 '정상 동작' 상태로 복원된 후에만 비로소 `[3단계: 06 가이드 300줄 슬라이싱]` 및 `core/` 순수 함수 승격에 착수한다.
