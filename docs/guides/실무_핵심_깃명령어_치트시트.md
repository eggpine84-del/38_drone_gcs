# 실무 필수 Git 명령어 TOP 20 치트시트

실무에서 가장 많이 쓰고, 이것만 알면 Git 문제 99%를 해결하는 20가지 핵심 명령어입니다.

---

### [Part 1] 매일 쓰는 4대 천왕 (1~4)
가장 기본이자 매일 반복하는 작업 흐름입니다.

1. **현재 작업 상태 확인**
   git status
   > 내가 어떤 파일을 수정했는지, 커밋할 준비가 되었는지 색상별로 보여줍니다.

2. **작업한 파일 장바구니에 담기 (스테이징)**
   git add .
   (특정 파일 1개만 담을 때: git add <파일명>)
   > 수정한 파일들을 다음 커밋 목록에 올립니다.

3. **로컬에 저장 도장 쾅 찍기**
   git commit -m "작업 내용 요약"
   > 작업 내역을 메모와 함께 내 컴퓨터에 안전하게 영구 저장합니다.

4. **GitHub로 쏘기 (원격 업로드 & Vercel 자동 배포)**
   git push origin master
   > 로컬의 커밋을 GitHub에 올립니다. (Vercel 상용 서버 자동 배포가 시작됩니다.)

---

### [Part 2] 코드 확인 및 이력 조회 (5~8)
내가 뭘 바꿨는지, 과거에 무슨 일이 있었는지 확인합니다.

5. **수정한 코드의 구체적인 차이(Diff) 확인**
   git diff
   > 커밋하기 전에 어떤 줄이 추가(+)되고 삭제(-)되었는지 빨간/초록색으로 보여줍니다.

6. **최근 커밋 기록 1줄씩 깔끔하게 보기**
   git log --oneline -n 10
   > 최근 10개의 커밋 내역을 한 줄 요약으로 깔끔하게 확인합니다.

7. **방금 한 커밋에서 바뀐 내용 자세히 보기**
   git show HEAD
   > 가장 마지막으로 저장한 커밋의 파일별 코드 수정 사항을 통째로 보여줍니다.

8. **누가 이 코드 줄을 썼는지 추적하기**
   git blame <파일명>
   > 파일의 각 라인을 누가, 언제, 어떤 커밋으로 수정했는지 범인을 찾아냅니다.

---

### [Part 3] 실수했을 때 긴급 복구 및 취소 (9~13)
망했을 때 당황하지 않고 되돌리는 비상 탈출구입니다.

9. **수정한 파일 전부 작업 전으로 깨끗하게 되돌리기**
   git restore .
   (특정 파일만 되돌릴 때: git restore <파일명>)
   > "아 방금 작업 망했다!" 할 때 마지막 커밋 시점으로 완전히 원상복구합니다.

10. **git add 로 잘못 담은 파일 빼기**
    git restore --staged <파일명>
    > 장바구니에 잘못 올린 파일을 다시 일반 수정 상태로 내려놓습니다.

11. **코드는 그대로 두고 방금 한 커밋만 취소하기 (가장 안전)**
    git reset --soft HEAD~1
    > 작성한 코드는 1줄도 안 지우고, 방금 친 git commit 도장만 쏙 취소합니다.

12. **방금 커밋 메시지 오타 고치기**
    git commit --amend -m "새로운 올바른 메시지"
    > 새 커밋을 만들지 않고 방금 한 커밋의 메시지나 빠뜨린 파일을 덮어씌웁니다.

13. **새로 만든 미추적 파일(잡동사니) 한 번에 청소하기**
    git clean -fd
    > Git이 추적하지 않는 새로 생성된 임시 파일이나 폴더를 싹 삭제합니다.

---

### [Part 4] 작업 임시 보관 (14~15)
다른 작업을 먼저 해야 할 때 서랍에 잠깐 넣어둡니다.

14. **작업 중이던 미완성 코드 서랍에 임시 보관하기**
    git stash
    > 작업 트리를 깨끗하게 비우면서 현재 작업을 서랍에 안전하게 숨깁니다.

15. **서랍에 넣어둔 작업 다시 꺼내오기**
    git stash pop
    > 임시 보관했던 코드를 다시 꺼내어 작업을 이어서 진행합니다.

---

### [Part 5] 원격 저장소 및 브랜치 관리 (16~20)
외부 서버와 싱크를 맞추거나 가지를 칠 때 씁니다.

16. **GitHub 최신 변경사항 내려받아 합치기**
    git pull origin master
    > 다른 곳에서 커밋된 최신 코드를 내 컴퓨터로 가져와 자동으로 합칩니다.

17. **내 코드 안 건드리고 원격에 새 커밋이 있는지 체크만 하기**
    git fetch origin
    > 로컬 파일을 변경하지 않고 원격 저장소의 최신 상태만 탐지합니다.

18. **현재 연결된 GitHub 주소 확인하기**
    git remote -v
    > 내 프로젝트가 어떤 GitHub 저장소와 연결되어 있는지 주소를 확인합니다.

19. **새로운 작업 브랜치 만들고 바로 이동하기**
    git checkout -b <새브랜치명>
    > 기존 코드에 영향 없이 안전하게 실험해 볼 새로운 작업 공간을 만듭니다.

20. **메인 브랜치로 다시 돌아오기**
    git checkout master
    > 작업하던 브랜치를 빠져나와 기준이 되는 메인 브랜치로 복귀합니다.
