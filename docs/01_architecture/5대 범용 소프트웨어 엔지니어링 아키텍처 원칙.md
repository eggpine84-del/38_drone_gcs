## 0. AI 에이전틱 엔지니어링 지휘 철학 (루트 통제 & 3대 사전 검증)

> **"내가 똑똑하다고 자만하지 말고, AI를 맹신하지도 말며, 룰과 템플릿으로 최적의 정석 답을 찾아가는 루트를 옥죈다."**

### ① 황금 3단계 사이클 (Gold Tri-Step)
1. **[아이디어 / 버그 발의]**: 요구사항 또는 이상 현상 접수
2. **[0번 Arch-Guard 직언]**: 예스맨 코딩 금지, 단순 땜질(B안) vs 구조적 근본 수술(A안) 대립 비교 선제안
3. **[확정 기획서 / 분석서 작성]**: 사장님이 승인한 정석 A안을 바탕으로 단 한 번에 무결점 S1 기획서 작성

### ② 3대 사전 검증 질문 (Tri-Gate Check)
1. **신원 검증 (Identity)**: 이 화면을 다루는 주체가 사장님 본인인가, 고객사 대리(Viewer)인가? (신원 불변 보장)
2. **영향 범위 (Blast Radius)**: 이 작업을 수행했을 때 내 설정만 바뀌는가, 남의 고객사 데이터까지 침범하는가? (침범률 0% 격리)
3. **1목적 1도구 (Tool-Purpose)**: 이 도구가 1장짜리 포스트잇(단일 갱신)인가, 다중 보관함(독립 관리)인가? (이종 차원 결합 영구 금지)

## 2. 계층별 상세 실천 가이드

### ① UI / Frontend
* **상태 복제 금지:** 하나의 상태가 State, Store, URL에 중복 존재하지 않도록 URL을 단일 진실의 원천으로 사용.
* **1목적 1도구:** 화면 이동은 `<a>` 링크/라우터로, 드롭다운/라디오는 화면 내부의 단순 필터/값 선택에만 국한.
* **정리(Cleanup) 필수:** 페이지 이탈 시 비동기 요청(`AbortController`), 타이머, 이벤트 리스너를 반드시 해제.

### ② 백엔드 / Backend
* **Stateless 원칙:** 서버 인스턴스는 상태를 갖지 않아야 수평 확장(Scale-out) 시 정합성이 유지됨.
* **프론트엔드 데이터 불신:** 클라이언트가 넘겨준 `userId`, `companyId`를 신뢰하지 않고, 반드시 세션/JWT 토큰 내부의 인가 정보를 대조.
* **멱등성 설계:** 동일한 결제/생성 요청이 네트워크 지연으로 중복 유입되어도 1회만 처리되도록 멱등키 보장.

### ③ 데이터베이스 / Database
* **물리적 무결성 강제:** 비즈니스 검증과 별개로 DB 레벨의 `NOT NULL`, `UNIQUE`, `FOREIGN KEY`를 반드시 선언.
* **테넌트 격리 강제:** 멀티테넌트 환경에서는 모든 쿼리에 테넌트 ID 조건을 강제하거나 RLS(Row Level Security)를 구성.
* **캐시 휘발성 인지:** 캐시는 원본이 아니므로 원본 데이터 갱신 시 즉시 무효화(Invalidate) 전략 실행.

### ④ 네트워크 & 인프라 / Network & Infra
* **기본 차단(Default Deny):** 모든 포트와 인바운드 트래픽은 닫아두고, 명시적으로 허용된 화이트리스트만 개방.
* **장애 격리:** 외부 통신 시 무한 대기를 막기 위해 엄격한 Connection/Read Timeout을 걸고 서킷 브레이커 적용.

### ⑤ 시스템 & 로우레벨 / System & Low-Level
* **자원 소유권(Ownership):** 자원(메모리, 소켓, 파일 디스크립터)을 할당한 주체가 수명 주기 종료 시점에 명시적으로 반환.
* **경합 조건(Race Condition) 차단:** 멀티스레드 환경의 공유 자원 접근 시 Mutex, Atomic 연산으로 원자성 보장.

## 3. 코드 작성 전/후 자가 진단 체크리스트 (5 Golden Questions)

- [ ] **Where is Truth? (진실의 원천):** 이 데이터의 원본이 오직 한 곳에만 정의되어 있는가? (중복 상태 없음)
- [ ] **Is it Isolated? (경계 격리):** 한 영역의 에러나 데이터 변경이 다른 영역(타 테넌트, 타 모듈)을 침범하지 않는가?
- [ ] **Can it Fail-Safe? (안전한 실패):** 권한 부족이나 예외 발생 시 비정상 실행 대신 안전하게 즉시 차단(Fail-Closed)되는가?
- [ ] **Is it Deterministic? (결정론적 동작):** 브라우저 새로고침, 재요청, 동일 입력에 대해 항상 일관된 결과를 반환하는가?
- [ ] **Is Resource Released? (자원 회수):** 작업 완료/화면 이탈 시 메모리, 네트워크 커넥션, 세션이 누수 없이 정리되는가?
