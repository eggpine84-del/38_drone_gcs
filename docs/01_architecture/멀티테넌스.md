# 멀티테넌스 아키텍처 및 격리 명세서 (Multi-Tenant Architecture Specification)

## 1. 최상단 하향식 파이프라인 (Top-Down Flow)
```
[유저 로그인] 
      │
      ▼
[최상단 관제탑 (Top-Down Context)]
  * FastAPI Session / Cookie 기반 단일 진입점 확정
  * Context 주입: tenant_id, db_path, role, allowed_menus 일체형 하향 주입
  * 하위 함수의 자의적 테넌트 추측(Bottom-up) 원천 차단
      │
      ├───────────────────────┬────────────────────────┬───────────────────────┐
      ▼                       ▼                        ▼                       ▼
 [슈퍼 관리자]          [개인 대시보드]           [테넌트1 (학원1)]       [테넌트2 (회사1)]
(플랫폼 총괄/대리)      (개인 작업실 격리)        (독한공부/원장/강사)     (에스엠무역/대표/직원)
```

## 2. 계층별 역할 및 권한 통제 (RBAC Matrix)

| 구분 | 대상 역할 | 조작 범위 및 권한 규칙 | 침범 방어선 |
| :--- | :--- | :--- | :--- |
| **슈퍼 관리자** | SUPER_ADMIN | * 전 시스템 총괄 관제<br>* 2단 스위처 기반 고객사 관제 진입 (뷰어 모드)<br>* 고객사 조직/강사 대리 관리 (Proxy Admin) | 관제 진입 시에도 사장님 본래 프로필 불변 유지 |
| **개인 대시보드** | 마스터 전용 | * 개인 메모, 퀵 캡처, 개인 위젯 단독 조작 | 타 테넌트 및 상용 DB 접근 완전 차단 |
| **사업장 대표** | OWNER / 원장 / 사장 | * 소속 테넌트의 모든 메뉴 및 설정 조작 가능<br>* 소속 강사/직원 계정 및 메뉴 배정 권한 전담 | 타 사업장 메뉴 및 데이터 침범 금지 (1:1 격리) |
| **소속 구성원** | MEMBER / 직급자 / 강사 / 직원 | * 대표가 허용한 메뉴만 조작 가능 (화이트리스트)<br>* 허용 외 메뉴 URL/API 직접 호출 시 차단 | 상위 관리자 메뉴 및 타 테넌트 데이터 침범 금지 |

## 3. 물리 스토리지 및 DB 1:1 대칭 격리 (Storage Isolation)

```
data/db/
├── system/
│   └── system.db ──────────────── [시스템 총괄] 플랫폼 관제 로그, 백업, 메트릭
├── personal/
│   └── personal.db ────────────── [개인 작업실] 개인 위젯, 퀵 메모, 독립 데이터
└── tenants/
    ├── sua_academy.db ─────────── [테넌트1: 학원1] 학생, 출결, 상담, 강사, 수납
    ├── tenant_biz_1789737602.db ─ [테넌트2: 회사1] 가격모니터링, 직원, 테넌트 설정
    └── {tenant_id}.db ─────────── [신규 테넌트] 자동 프로비저닝 1:1 전용 DB
```

* **원칙**: 모든 테넌트는 물리적으로 분리된 독립 SQLite/PostgreSQL 데이터베이스를 사용한다.
* **격리 보증**: 테넌트 간 테이블 조인, 공용 뷰, 공유 저장을 영구 금지한다.

## 4. 단일 진실 공급원 체계 (SSoT / SST)

1. **보안 및 인증 (SST - Single Source of Truth)**
   * 위치: `.env` 환경 변수 단일 통제 (`MASTER_ADMIN_PASSWORD` 등).
   * 규칙: INI 파일 내 비밀번호 평문 저장 영구 금지, 위반 시 무인 커밋 훅 차단.
2. **사업장 브랜드 및 설정 (SSoT - Single Source of Truth)**
   * 위치: DB `tenant_settings` 테이블 (1순위 오버라이드) ➔ INI 파일 (Seed Fallback).
   * 범위: 본문 상단 헤더(`app_title`), 사이드바 메뉴, 프로필 명칭 100% 실시간 일괄 동기화.
3. **슈퍼어드민 대리 관리 (Proxy Admin)**
   * 고객사 테넌트 뷰어 모드 진입 시, 마스터 프로필을 유지한 채 해당 고객사의 DB 컨텍스트만 안전하게 주입받아 대리 설정 수행.

## 5. 핵심 방어선: 암묵적 폴백 박멸 (Fail-Fast Gate)

```
[비즈니스 함수 호출]
        │
        ▼
[Fail-Fast Gate] ─── db_path 또는 tenant_id 누락/공백? ───► YES ───► [즉시 ValueError 차단]
        │ (NO: 유효한 테넌트 컨텍스트 확인)                                 (기본값 sua_academy 오염 차단)
        ▼
[해당 테넌트 전용 DB 실행]
```

* **차단 대상**: `student_db`, `attendance_db`, `counseling_db`, `teacher_storage`, `settings_core` 등 비즈니스 계층 전수.
* **효과**: 테넌트 식별자가 없는 요청이 조용히 독한공부(`sua_academy.db`)로 흘러가 데이터를 읽거나 덮어쓰는 나비효과를 원천 박멸.
* **무인 검증**: 회귀 테스트 및 커밋 훅(Zero-Mutation, Pin-Test First)을 통해 영구 보존.
