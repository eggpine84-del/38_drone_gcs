## 1. 핵심 요약 및 우리 프로젝트(AGENTS.md / 룰즈) 연계 시사점

### (1) 카파시가 정의한 '바이브 코딩의 3대 질병' (AI의 고질병)
1. **묻지도 않고 멋대로 가정한 다음 그대로 달려간다.**
2. **헷갈려도 정리하지 않고 되묻지도 않는다.**
3. **시키지도 않은 코드까지 건드린다 (주변 코드 파괴, 사이드 이펙트).**
> 카파시: *"이 모든 일이 CLAUDE.md에 지시를 넣어서 고쳐보려 했는데도 여전히 일어나더라."*

### (2) 왜 단순 프롬프트 / 규칙 문서만으로는 실패하는가?
- **시스템 프롬프트가 아닌 유저 메시지 레벨**: `CLAUDE.md`는 Anthropic 공식 문서상 유저 메시지로 전달되어 **'명령이 아니라 부탁'**에 불과함 (엄격하게 지켜진다는 보장이 없음).
- **매일 아침 기억을 잃는 신입**: 새 세션마다 컨텍스트 윈도우가 리셋됨.
- **`/compact`의 치명적 함정**: 대화 압축 시 스킬 목록(메뉴판)을 상실하여 세션 후반부로 갈수록 멍청해짐.
- **컨텍스트 길이와 성능 저하**: 32k 토큰만 넘어가도 13개 모델 중 11개의 성능이 절반 이하로 급락.
- **비대한 규칙의 역효과**: '깨끗한 코드를 써라' 같은 자명한 지침으로 가득 찬 비대한 파일은 AI가 진짜 중요한 지시를 무시하게 만듦. (*"10줄이 20줄보다 잘 지켜진다. 2번 이상 틀린 사고의 자국만 적어라."*)

### (3) 상위 1%의 해결책: "확률을 결정으로 끌어와라" (하네스 Harness 구축)
> **"부탁(프롬프트)을 멈추고, 어길 수 없는 장치(Harness/Hook/Deterministic Check)로 만들어라."**

1. **"다 됐어요"를 시스템이 원천 차단하기 (Stop Hook)**
   - "이 기능 만들어줘" 대신, 성공 기준(테스트)을 먼저 작성하게 함.
   - 턴을 종료하려고 할 때 Hook이 자동으로 검사를 돌리고, 통과하지 못하면 턴 종료 자체를 차단.
   - **반드시 포함할 지침**: *"테스트는 고치지 말고 코드를 고쳐라"* (켄트 벡의 경고: AI가 통과시키려고 테스트를 약화/삭제하는 컨닝 차단).
2. **저장 / 커밋 순간의 강제 검사 (Pre-commit / Guard)**
   - 마이그레이션 이력이나 문법 규칙(예: let 금지 등)을 프롬프트로 부탁하지 않고, 검사 실패 시 저장/커밋 자체가 불가능하게 만듦.
3. **메인 브랜치 머지 자동 차단**
   - 혼자 개발하더라도 메인 직접 커밋을 막고, 자동 검사(CI) 통과 전에는 머지 버튼이 비활성화되도록 물리적 장치 구축.
