# 시스템 보안 4대 역발상 헌법

모든 공격(다크)과 방어(화이트)를 관통하는 컴퓨터 공학의 4대 원론적 결함과 범용 물리 게이트.

---

## 1. 해킹의 기원: 폰 노이만 구조의 원죄

1945년 존 폰 노이만이 현대 컴퓨터 구조를 확립할 때, **"명령어(Code)와 데이터(Data)를 동일한 메모리 버스/공간에 적재한다"**는 설계를 채택했다.

* **본질적 결함**: 하드웨어와 해석기(CPU, SQL 엔진, 브라우저, 쉘)는 읽어 들인 바이트가 개발자가 의도한 **'명령어'**인지, 외부에서 흘러들어온 **'단순 데이터'**인지 스스로 구분하지 못한다.
* **해킹의 탄생**: *"데이터 영역에 실행 코드를 밀어 넣어, 엔진이 내 데이터를 실행하게 만든다."* — 이것이 해킹의 시초이자 모든 공격의 뿌리이다.
* **역발상 보안의 원칙**: 공격 툴이나 기교를 쫓아다니지 말고, **"시스템이 작동하는 4가지 물리적 통로(입력, 상태, 신원, 자원)"**에 기계적 차단벽(Gate)을 세운다.

---

## 2. 해킹의 4대 핵심 원론적 무기 (The 4 Primitives)

세상에 존재하는 수만 가지 CVE 취약점과 공격 기법은 아래 4가지 물리적 축으로 100% 수렴한다.

```
+------------------------------------------------------------------------+
|                     해킹의 4대 원론적 무기 (공격 vs 방어)                |
+------------------------------------------------------------------------+
| 1. 경계 붕괴 (Injection)      : "데이터를 코드로 오인시켜 실행한다"        |
| 2. 상태 교란 (Race & State)    : "확인(Check)과 사용(Use) 사이를 찢는다"    |
| 3. 신뢰 왜곡 (Auth & Context)  : "시스템이 당연히 믿는 전제를 속인다"      |
| 4. 자원 고갈 (Resource Trap)   : "1의 힘으로 10,000의 연산을 유도한다"     |
+------------------------------------------------------------------------+
```

---

### 제1무기. 경계 붕괴 (Boundaries Collapse / Injection)

> **"데이터와 코드의 경계를 무너뜨려, 외부 입력을 실행 엔진으로 승격시킨다."**

* **공격 원리**: 해석기(Parser)는 입력값에 문법적 특수문자(`'`, `;`, `\0`, `0x90`, 시스템 태그)가 섞여 들어오면 해석 흐름을 바꾼다.
* **공격 양상 (Dark)**:
  * 메모리: 버퍼 오버플로우 (데이터 버퍼를 넘쳐 CPU의 리턴 주소(RIP) 장악).
  * 웹/DB: SQL 인젝션, XSS, OS 커맨드 인젝션.
  * AI/LLM: 프롬프트 인젝션 (시스템 프롬프트 무력화 및 제어권 탈취).
* **물리적 방어선 (White)**:
  * **해석기 앞단 물리 격리**: 컴파일된 쿼리에 값만 바인딩 (Prepared Statement).
  * **실행 불능 구역화**: W^X(쓰기 가능한 공간은 실행 불가), NX Bit, 엄격한 입력 DTO/Pydantic 정규화.

---

### 제2무기. 상태 교란 (Race Condition / TOCTOU)

> **"확인하는 순간(Check)과 실행하는 순간(Use)의 미세한 시간차를 찢는다."**

* **공격 원리**: 시스템은 원자적(Atomic)이지 않다. 멀티스레드, 분산 환경, 비동기 루프에서는 "조건 검사"와 "실제 반영" 사이에 나노초~밀리초 단위의 시차가 발생한다.
* **공격 양상 (Dark)**:
  * 금융/에스크로: 더블 스펜딩(Double-Spending), 동시 다발 출금 요청을 통한 잔액 음수화.
  * 블록체인: Reentrancy(재진입) 공격 (자금 전송 함수 완료 전 재호출).
  * OS/임베디드: 심볼릭 링크 레이스, 플래그 검사 직후 파일 바꿔치기.
* **물리적 방어선 (White)**:
  * **임계 영역 원자화**: 비관적 락(`SELECT FOR UPDATE`), 원자적 비교-교환(Atomic CAS).
  * **조건부 원자 갱신**: `UPDATE accounts SET balance = balance - :amt WHERE balance >= :amt`.
  * **패턴 준수**: Checks-Effects-Interactions (상태를 먼저 차감한 후 외부 호출).

---

### 제3무기. 신뢰 왜곡 (Impersonation / Broken Trust Boundary)

> **"시스템이 편의상 당연하게 믿고 넘기는 식별/인가 체계를 속인다."**

* **공격 원리**: 시스템은 매번 모든 것을 검증하기 번거로우므로 토큰, 세션, IP, 내부망(VPC), 클라이언트 요청 필드를 맹신하는 버릇이 있다.
* **공격 양상 (Dark)**:
  * 웹/API: IDOR / BOLA (남의 `order_id` 파라미터만 변조하여 결제 취소/열람).
  * 클라우드: SSRF (웹서버를 속여 내부 메타데이터 서버 `169.254.169.254` 호출 및 IAM 탈취).
  * 임베디드: 버스(I2C/SPI) 신호 도청 및 가짜 센서 패킷 인젝션.
* **물리적 방어선 (White)**:
  * **제로 트러스트(Zero Trust)**: 내부망, 세션, 클라이언트가 보낸 금액/권한을 일절 불신.
  * **소유권 원자 대조**: `WHERE id = :id` 단독 조회 영구 금지 ➔ 반드시 `WHERE id = :id AND owner_id = :current_user` 강제.

---

### 제4무기. 자원 고갈 (Asymmetric Exhaustion / DoS)

> **"공격자의 1바이트 비용으로, 방어자의 10만 바이트 연산/메모리를 태운다."**

* **공격 원리**: 연산 복잡도($O(N^2)$)나 프로토콜 대기 시간의 비대칭성을 악용하여 하드웨어 자원(CPU, 메모리, 소켓, DB 커넥션)을 질식시킨다.
* **공격 양상 (Dark)**:
  * 네트워크: Slowloris (헤더를 1바이트씩 늦게 보내 웹서버 스레드 풀 전멸).
  * 엔진: ReDoS (정규표현식 백트래킹을 유발하는 문자열로 CPU 100% 동결), ZIP/XML 폭탄.
  * AI/클라우드: Denial of Wallet (수백만 토큰 연산 유도로 API 비용 파산).
* **물리적 방어선 (White)**:
  * **무한대 거부**: 모든 I/O(DB, HTTP, RPC, 센서)에 강제 타임아웃(Timeout) 3초 부착.
  * **배압 제어(Backpressure) & 고정 풀**: 동적 무제한 큐 금지, Ring Buffer, `LIMIT` 강제, Rate Limiting.

## 3. 전 도메인 범용 대응 매트릭스 (4대 물리 게이트)

| 4대 물리 게이트 | 웹 / 백엔드 (Python/Go/DB) | 임베디드 / IoT (C/Rust/MCU) | 블록체인 / 스마트컨트랙트 | AI / LLM 파이프라인 |
| :--- | :--- | :--- | :--- | :--- |
| **Gate 1.<br>정규화 격리**<br>*(경계 붕괴 차단)* | • Prepared Statement 필수<br>• DTO/Pydantic 통과 전 원시 입력 접근 금지 | • 고정 버퍼(`snprintf`) 강제<br>• MPU/MMU 하드웨어 W^X 적용 | • `abi.decode` 엄격 검증<br>• `delegatecall` 임의 실행 차단 | • 시스템 프롬프트/유저 입력 물리 분리<br>• 샌드박스 밖 실행 금지 |
| **Gate 2.<br>권한-자원 바인딩**<br>*(신뢰 왜곡 차단)* | • 식별자 단독 조회 금지 (`AND owner_id` 강제)<br>• 클라이언트 전송 가격/역할 100% 무시 | • 하드웨어 서명 칩(Secure Element) 인증<br>• 메모리 링 격리 (Ring 0 vs 3) | • `msg.sender == owner` 제어자<br>• Nonce 기반 리플레이 방지 | • 모델 출력물 실행 전 권한 재검증<br>• 사용자 세션별 Tool 권한 격리 |
| **Gate 3.<br>임계 영역 단일화**<br>*(상태 교란 차단)* | • 조건부 차감 쿼리(`WHERE val >= :amt`)<br>• Row Lock (`SELECT FOR UPDATE`) | • 인터럽트 비활성화(`cli()`)<br>• 하드웨어 원자적 CAS 연산 | • Checks-Effects-Interactions 준수<br>• ReentrancyGuard 재진입 락 | • RAG 벡터DB 업데이트 락<br>• 모델 캐시 원자적 스왑 |
| **Gate 4.<br>물리적 자원 상한**<br>*(자원 고갈 차단)* | • 모든 통신 Timeout 3초 강제<br>• 모든 목록 조회 `LIMIT 50` 강제 | • 하드웨어 와치독(Watchdog) 가동<br>• 동적 `malloc` 금지, 고정 버퍼 | • 가스 상한(Gas Limit) 설정<br>• 무한 루프 가능 배열 순회 금지 | • 요청당 Max Token 강제<br>• 프롬프트 길이 사전 필터링 |

## 4. 실무 코드 리뷰 & 핀테스트 필수 판정표

코드를 배포하거나 PR을 승인하기 전, 아래 4대 단언(Assertion) 중 단 하나라도 미충족 시 배포를 즉각 중단(Block)한다.

```python
# [보안 4대 물리 게이트 실무 검증 단언문]

# 1. 경계 붕괴 단언: SQL/쉘 조립에 f-string이나 % 포맷팅이 1곳이라도 있는가?
assert "f\"SELECT" not in code and "f'SELECT" not in code, "CRITICAL: Prepared Statement 위반"

# 2. 상태 교란 단언: 잔액 차감 시 단순 SELECT-UPDATE 구조인가, 원자적 조건부 갱신인가?
assert "WHERE balance >= :amount" in update_query, "CRITICAL: 동시성 Race Condition 위험"

# 3. 신뢰 왜곡 단언: 데이터 수정/조회 시 본인 소유권(Owner) 조건이 누락되었는가?
assert "owner_id = :current_user" in query, "CRITICAL: BOLA/IDOR 취약점 노출"

# 4. 자원 고갈 단언: 외부 네트워크/DB 호출에 타임아웃이 명시되어 있는가?
assert "timeout=" in network_call, "CRITICAL: 자원 고갈 무한 대기 위험"
```

## 5. 결론: 상호 불신(Zero Trust)의 미학

보안은 "착한 사용자"를 기대하는 순간 무너진다.  
**"입력은 오염되어 있고, 시간은 찢어지며, 신원은 위조되고, 자원은 유한하다."**  
이 4대 명제를 시스템의 물리적 뼈대에 새기는 개발자만이 침몰하지 않는 소프트웨어를 만든다.
