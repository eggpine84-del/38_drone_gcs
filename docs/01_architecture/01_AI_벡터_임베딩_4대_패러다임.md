# AI 및 벡터 임베딩 4대 핵심 패러다임 (Vector Embeddings & Semantic AI)

자연어의 '의미와 뉘앙스'를 수학 공간으로 변환해 현대 생성형 AI(LLM)와 시맨틱 검색(RAG)을 탄생시킨 4대 핵심 원리.

---

## 1. 고차원 좌표 압축 (Dense Vector Projection) ➔ [대표: OpenAI Embeddings, BERT, FastText]

> **"단어의 '의미(Meaning)'를 컴퓨터가 계산할 수 있는 '숫자 좌표(기하학 공간)'로 바꾼다."**

* **기존 상식**: 
  - 단어나 문장을 검색할 때 글자 그대로 일치하는지(`"사과" == "사과"`) 단순 텍스트 비교를 했다.
  - "휴대폰"과 "스마트폰", "애플"과 "아이폰"처럼 철자는 다르지만 같은 의미를 가진 단어를 전혀 이해하지 못함.
* **발상의 전환**: 
  - 언어의 모든 의미를 768차원, 1,536차원 같은 고차원 공간의 **연속적인 점(Dense Vector)**으로 투영한다.
  - 단어 간의 개념적 거리가 가까울수록 좌표 공간 상에서도 가깝게 뭉치게 학습시킨다.
* **핵심 효과**:
  - 의미를 수학 연산으로 조작 가능: `"왕(King)" - "남자(Man)" + "여자(Woman)" = "여왕(Queen)"`
  - 오타, 동의어, 다국어 간에도 의미가 같으면 동일한 좌표군으로 묶여 언어 장벽이 사라짐.
* **대표 활용**:
  - 시맨틱 검색 엔진, 다국어 번역 모델, 추천 시스템(비슷한 취향의 유저/상품 군집화).

## 2. 코사인 유사도 (Cosine Similarity) ➔ [대표: Numpy, Scikit-learn, PyTorch]

> **"글의 유사도를 잴 때 단어 개수를 세지 않고, '화살표가 가리키는 각도'만 잰다."**

* **기존 상식**: 
  - 두 문서가 비슷한지 비교할 때 겹치는 단어의 빈도수를 셌다(TF-IDF).
  - 글의 길이가 길어지면 단어가 많이 나와서 실제로는 다른 내용인데도 유사하다고 왜곡되는 한계 발생.
* **발상의 전환**: 
  - 벡터 화살표의 길이(문서의 분량)는 무시하고, 원점에서 뻗어나가는 **두 화살표 사이의 사잇각(Cosine Angle)**만 내적(Dot Product)으로 측정한다.
* **핵심 효과**:
  - 1줄짜리 요약문과 10페이지짜리 전문 문서라도 **주제와 뉘앙스가 같으면 각도가 0도(유사도 1.0)에 수렴**하여 완벽하게 매칭.
  - 연산이 단순 곱셈과 덧셈(내적)뿐이므로 수백만 건의 비교를 순식간에 끝냄.
* **대표 활용**:
  - 챗봇 지식 베이스 질의 매칭, 문서 표절 검사, 이미지-텍스트 유사도 매칭 (CLIP).

## 3. 계층형 내비게이션 그래프 (HNSW) ➔ [대표: Pinecone, Milvus, Chroma, pgvector]

> **"1,000만 개 벡터를 일일이 다 비교하지 않고, '고속도로 톨게이트'처럼 건너뛰며 찾는다."**

* **기존 상식**: 
  - 질문 벡터와 가장 비슷한 문서를 찾으려면 1,000만 개 문서 벡터와 일일이 각도를 계산해야 한다 ($O(N)$ 전수 조사).
  - 데이터가 10만 건만 넘어가도 검색 시간이 수 초 이상 걸려 실시간 서비스가 불가능해짐.
* **발상의 전환**: 
  - '6단계 분리(작은 세상 네트워크)' 원리를 계층형 그래프(Hierarchical Navigable Small World)로 구축.
  - 상위 계층(고속도로)에서는 큼직하게 건너뛰며 대략적인 위치를 찾고, 하위 계층(골목길)으로 내려와 정밀하게 좁힌다.
* **핵심 효과**:
  - 1,000만 건 데이터 중 가장 유사한 상위 5개를 **$O(\log N)$ (불과 2~5ms)** 만에 번개처럼 찾아냄.
  - 최신 모든 상용 벡터 DB(Pinecone, Weaviate, pgvector 등)가 초고속 검색을 달성한 1등 공신.
* **대표 활용**:
  - 실시간 RAG (검색 증강 생성), 수천만 건 규모의 전자상거래 유사 이미지 검색.

## 4. 지능형 문맥 청킹 (Context Chunking & Overlap) ➔ [대표: LangChain, LlamaIndex, RAG 파이프라인]

> **"책 한 권을 통째로 넣으면 멍청해지니, '의미가 끊기지 않게 꼬리를 물며' 잘게 썰어 넣는다."**

* **기존 상식**: 
  - 긴 PDF나 매뉴얼을 500자 단위로 무식하게 칼로 자르듯 분할했다.
  - 핵심 문장이 중간에서 반 토막 나거나, 앞뒤 맥락이 날아가 AI가 엉뚱한 거짓말(환각, Hallucination)을 생성.
* **발상의 전환**: 
  - 의미의 최소 단위(마크다운 헤더, 문단, 함수 블록)를 보존하며 자른다.
  - 분할 경계마다 앞뒤 10~20%의 **슬라이딩 윈도우 오버랩(Sliding Overlap)**을 주어 맥락의 연결고리를 유지한다.
* **핵심 효과**:
  - AI(LLM)의 제한된 컨텍스트 윈도우에 **가장 밀도 높은 정답 후보 조각만 핀포인트로 주입**.
  - 문서가 아무리 방대해도 환각(거짓말) 0%의 칼 같은 팩트 기반 답변을 유도.
* **대표 활용**:
  - 사내 규정/사규/법률/의학 RAG 시스템, 기술 문서 질의응답 봇.

## 5. 실무 AI 개발 체크리스트

| 검토 항목 | 하수 (비용 낭비/느림) | 고수 (4대 패러다임 적용 방식) |
| :--- | :--- | :--- |
| **유사도 검색** | 무조건 고가의 클라우드 벡터 DB(월 $100+) 구독 | 소규모는 `Numpy dot` 또는 `sqlite-vec` / `pgvector`로 내부에서 무료 처리 |
| **문서 분할** | 문자열 길이로 무작위 자르기 | 헤더/문단 단위 청킹 + 50자 오버랩으로 맥락 보존 |
| **대용량 색인** | 전체 벡터를 매번 $O(N)$ 전수 스캔 | HNSW 인덱스 걸어서 $O(\log N)$ (2ms 컷) 고속 서치 |
| **검색 결과 주입** | 연관 문서 20개를 통째로 프롬프트에 쏟아붓기 | 상위 3~5개 알짜 청크만 엄선 주입해 토큰 비용 80% 절감 |
