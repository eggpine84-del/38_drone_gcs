# [보일러플레이트] 프로젝트 도메인 헌법 및 5대 뼈대 도출 표준
# Universal Project Constitution & 5-Step Foundation Blueprint

> **철칙**: `CONSTITUTION.md` 1장 확정 시 `일일_작업일지.md` 5대 뼈대 100% 자동 도출. 5번 Green 전 UI/피처 조기 분가 영구 금지.

---

### 1. 헌법 ➔ 5대 뼈대 1:1 도출 매트릭스

| 헌법 조항 (SSOT 입력) | ➔ | 일지 5대 뼈대 (자동 도출) | 구현 핵심 가드 |
| :--- | :---: | :--- | :--- |
| **제1조. 4대 공리 (Axioms)** | ➔ | **1. [feat] 순수 코어 상태머신** | 외부 I/O 0건, Side-Effect 0건 순수 함수 |
| **제2조. 데이터 스키마 (SSOT)** | ➔ | **2. [feat] 저장소 중립 원장 저장소** | 인메모리 & 경량 SQLite 듀얼 드라이버 지원 |
| **제3조. 상태 전이 및 금기 (Invariants)**| ➔ | **3. [feat] 도메인 비즈니스 Shell 서비스** | 중복 개설 차단, 실패 시 원장 오염 0% 방어 |
| **제4조. 기본 시나리오 (Simple)** | ➔ | **4. [feat] 기본 단발 워크플로우 API** | 단일 봉투(`{"success", "data", "error"}`) 계약 검증 |
| **제5조. 복합 시나리오 (Complex)** | ➔ | **5. [feat] 복합 단계별 워크플로우 API**| 단계별 상태 전이, 불변량(Invariant) 보존, 멱등성 검증 |

---

### 2. 프로젝트 헌법 1장 서식 (`docs/{프로젝트}/CONSTITUTION.md`)

```markdown
# [프로젝트명] 시스템 헌법 (PROJECT CONSTITUTION)
1. **목적**: 시스템 존재 이유 및 방어 대상 위험/도메인 문제 정의
2. **4대 공리**: ①선행조건 필수(데이터 무결성) ②불변량 보존(Conservation/Zero-Loss) ③권한배타성(주체 분리) ④단방향 종결(종결 상태 불변성)
3. **최소 스키마**: `{"id":str, "mode":str, "owner":str, "target":str, "total_value":int, "processed_value":int, "status":str}`
4. **2대 시나리오**: ①단발 처리(1회 요청 즉시 원자적 완결) ②복합 워크플로우(1차 검증승인 -> 2차 처리 -> 중도 예외 시 원복/보존)
5. **3대 금기**: 선행 조건 없는 상태 전이 금지 | 종결(Terminal) 상태 재조작 금지 | 인가되지 않은 임의 처리 금지
```

```markdown
- [ ] **2. [feat] 저장소 중립형 불변 원장 저장소(Repository: 인메모리 & 경량 DB 듀얼 지원) 구축**

- [ ] **5. [feat] 복합형 단계별 워크플로우 및 상태/불변량 멱등 보존 검증**
```
