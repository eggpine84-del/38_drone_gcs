# 실무 소프트웨어 3대 분리(로직·방어·테스트) 및 멀티 테넌트 방어 아키텍처

> **원칙**: 소프트웨어 개발의 90%는 코드를 치는 행위가 아니라, 시스템이 커져도 무너지지 않도록 **[로직] - [방어] - [테스트]**를 명확히 분리하고 방어선을 구축하는 엔지니어링에 있다.

---

## 1. 왜 시중 교육과 외주 시장에서는 이를 알려주지 않는가?

### (1) 강의/유튜브의 비즈니스 모델: "쉽게 보여야 팔린다"
- 시중의 유튜브, 부트캠프, 유료 강의는 "누구나 3일 만에 뚝딱 만드는 웹 대시보드"라고 홍보해야 결제가 일어납니다.
- 만약 첫날부터 "소프트웨어 3대 분리, 멀티 테넌트 경계 격리, 선행 핀-테스트"를 가르치면 수강생의 95%가 환불하고 이탈합니다.
- 따라서 오직 마우스로 정상 클릭했을 때 화면이 예쁘게 뜨는 껍데기(Happy Path)만 가르치고, 뒤에서 데이터가 꼬이거나 다른 회사 화면이 유출되는 진짜 실무 결함은 철저히 숨깁니다.

### (2) 일반 AI 코딩 도구의 한계: "당장 돌아가는 땜질 스니펫"
- 챗GPT 등 일반 AI에게 "이 기능 만들어줘"를 요청하면, 생각 없이 한 파일에 SQL, HTML, if문, try-except를 짬뽕한 100줄짜리 스니펫을 즉답합니다.
- 방어선도 없고, 테스트도 없고, 격리도 없습니다.
- 사용자는 당장 화면이 뜨니 만족하고 복사하지만, 2~3달 뒤 아무도 손댈 수 없는 거대한 프랑켄슈타인 레거시 지옥에 갇히게 됩니다.

### (3) 외주 업계의 보이지 않는 이해관계
- 외주 개발사가 코드를 처음부터 [로직 - 방어 - 테스트]로 완벽하게 짜서 납품하면 버그가 발생하지 않습니다.
- 버그가 없으면 유지보수비와 추가 개발비를 청구할 수 없습니다.
- 1개 파일에 스파게티로 얽어놓아야, 추후 다른 사업장 기능을 추가할 때 "구조가 꼬여서 전면 재구축해야 한다"며 추가 비용을 영구 청구할 수 있습니다.

## 2. 실무 소프트웨어 3대 분리 (삼위일체 아키텍처)

현대 톱티어 빅테크(토스, 쿠팡, 구글, 넷플릭스)는 아래 3대 분리를 강제하며, 이를 지키지 않은 코드는 코드 리뷰에서 즉각 반려(Reject)되어 깃허브 머지가 차단됩니다.

| 구분 | 비유 | 담당 업무 | 현업 공식 명칭 | 핵심 구현 규칙 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 로직** | **은행 창구 직원** | 비즈니스 본질 연산, 화면 렌더링, 통장 발급 | **Pure Core / Domain Layer (DDD)** | DB, 네트워크, 파일, 시간, 랜덤 등 외부 잡음이 0건인 **순수 함수(Pure Function)**로만 20~30줄 작성 |
| **2. 방어** | **정문 청원경찰 & 금고문** | 신분증 검사, 위조지폐 차단, 테넌트 격리 | **Guard / Interceptor / Validation Layer** | 비즈니스 로직에 닿기 전 문 입구에서 **유효성, 권한, 테넌트 식별자를 100% 불신 검증** |
| **3. 테스트** | **금융감독원 감사팀** | 경찰과 직원이 규정을 지키는지 24시간 감시 | **TDD / Pin-Test / CI Pipeline** | 기능 구현 전 실패 테스트(Red) 선작성 후 통과(Green) 보증, 1초 전수 회귀 검증 |

### 왜 섞어 쓰면 망하는가?
- 창구 직원이 돈 세면서(`로직`) 동시에 손님 신분증 검사하고(`방어`) 금고문 단속까지 혼자 하려니 코드가 500줄로 비대해집니다.
- 바빠서 신분증 검사를 깜빡하는 순간, **에스엠무역 손님에게 독한공부 통장을 쥐여주는 치명적 상태 오염(Cross-Tenant Leakage)**이 터집니다.

## 3. 방어 코드 집중 관리 시스템 (글로벌 실무 인프라)

대규모 시스템에서는 비즈니스 코드 안에 방어용 `if`문이나 `try-except`를 개별 작성하지 않고, 방어만 집중 전담하는 별도 계층을 둡니다.

1. **OPA (Open Policy Agent - 정책 전담 엔진)**:
   - 넷플릭스, 구글 표준 오픈소스.
   - 비즈니스 서버는 "이 유저가 이 테넌트에 접근해도 되는가?"를 OPA 엔진에 질의하고, OPA가 Allow/Deny만 판정하여 비즈니스 코드에서 권한 검사 코드를 완전히 격리합니다.
2. **Netflix Hystrix & Resilience4j (장애/예외 격리 전담 프레임워크)**:
   - 장애 발생 시 서킷 브레이커(전기 차단기)를 내려 시스템 전체 다운을 방지하고 안전한 격리 폴백을 전담합니다.
3. **API Gateway (성문 전담 방어 서버: Kong, Cloudflare 등)**:
   - 메인 애플리케이션 앞단에 별도 서버를 두어 DDoS 차단, 악성 파라미터 필터링, 테넌트 식별 검사를 100% 선행 흡수합니다.

## 4. 멀티 테넌트 SaaS의 뼈대 vs 디테일(경계면)

단독 주택(단일 학원 전용)을 아파트(멀티 테넌트 SaaS)로 리모델링할 때 가장 위험한 것은 **'묵시적 기본값(Silent Fallback)'**입니다.

### (1) 묵시적 기본값의 함정
- 과거 코드: `tenant_id = request.get("tenant_id") or "tenant_sua_academy"`
- 화면이 하얗게 죽는 에러를 막기 위해 심어둔 친절한(?) 기본값이, DB 이관 시 파일 부재 상황과 결합하여 에스엠무역 화면에 독한공부를 강제 소환하는 시한폭탄이 되었습니다.
- **해결 원칙 (Fail-Fast)**: 식별자가 없으면 조용히 기본 화면으로 넘어가지 말고, 즉시 에러를 발생시키거나 사업장 선택 페이지로 강제 격리해야 합니다.

### (2) 글로벌 빅테크의 크로스 테넌트 데이터 유출 참사 사례
- **OpenAI (ChatGPT) 2023년 3월 참사**: Redis 캐시 키 충돌로 다른 사용자의 대화 목록, 제목, 신용카드 뒷자리가 전 세계에 노출되어 10시간 이상 전면 셧다운 및 CEO 공식 사과.
- **Steam 2015년 크리스마스 참사**: 캐싱 서버 설정 오류로 무작위 타인의 장바구니 및 구매 개인정보가 노출.
- **Slack 세션 충돌 버그**: 워크스페이스 전환 중 세션 토큰 오염으로 타 회사 비공개 채널 목록이 순간 노출.

### 6. 빅테크 5대 인프라 격리 관문 (Enterprise External Gateways)
> 비즈니스 로직(Core)에 섞지 않고 시스템 외곽으로 100% 분리·위임하는 5대 전문 센터.

| 관문 (비유) | 실무 시스템 | 비즈니스 로직 분리 역할 (100% 격리) |
| :--- | :--- | :--- |
| **1. 방어 (성문 문지기)** | Kong, API Gateway | 서비스 단일 입구에서 악성 차단·테넌트 식별·단일 관문 라우팅 전담 |
| **2. 관측 (CCTV 관제탑)** | Sentry, Datadog | 코드 내 print 전면 배제, 전 서버 에러·로그·메트릭 중앙 실시간 감시 |
| **3. 금고 (중앙 보안 금고)**| Vault, AWS Secrets | DB암호/API키/설정 파일 분산 금지, 암호화된 중앙 금고 단일 보관 |
| **4. 출입증 (통합 인증소)**| Keycloak, Okta SSO | 개별 로그인 로직 중복 금지, 중앙 세션·토큰 단일 발급 및 회수 |
| **5. 우체국 (비동기 큐)**   | Kafka, RabbitMQ | 알림·대량 정산 등 지연 I/O를 로직과 섞지 않고 메시지 큐 비동기 처리 |
