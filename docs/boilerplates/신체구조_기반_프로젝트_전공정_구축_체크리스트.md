# [보일러플레이트] 인체 시스템 기반 소프트웨어 전공정 구축 마스터 체크리스트
# Human Anatomy-Based End-to-End Engineering Checklist

본 체크리스트는 프로젝트를 백지(Zero) 상태에서 시작해 결함이나 누수(누락·상태오염·설계붕괴) 없이 완제품까지 빌드하기 위한 표준 엔지니어링 체크리스트입니다.

---

### [운용 원칙: 2가지 적용 방식]

1. **신규 프로젝트 전체 구축 (거시적 구축)**:
   - 처음부터 모든 뼈와 살을 100% 만드는 것이 아니라, **가장 단순한 핵심 데이터 1개만으로 머리부터 발끝까지 뚫린 최소 관통선(Walking Skeleton)**을 아래 0~8단계로 먼저 1회 완주하여 시스템이 살아서 숨 쉬게 만듭니다.
2. **개별 기능/모듈 단위 이식 (미시적 추가)**:
   - 이미 살아 숨 쉬는 시스템 뼈대 위에 새로운 장기(기능)를 추가할 때도 동일하게 0~8단계를 미니 루프로 반복하여 이식합니다.

---

```text
[0. 유전자/DNA] ➔ [1. 골격/뼈대] ➔ [2. 면역/테스트] ➔ [3. 심장/코어] ➔ [4. 혈관/통신] ➔ [5. 신경/통합] ➔ [6. 외피/UI] ➔ [7. 종합검진] ➔ [8. 출산/배포]
```

---

### [Phase 0. 유전자(DNA) 설계 — 기획 및 제약조건 수립]
*어떤 생명체를 만들 것인지 청사진과 절대 규칙을 정의하는 단계입니다.*

- [ ] 1. **단일 목적 정의**: 이 시스템(또는 기능)의 핵심 단일 책임을 1줄로 명시했는가?
- [ ] 2. **입출력(I/O) 규격 확정**: 시스템에 주입될 입력(Input)과 기대 결과(Output)의 형태를 구체화했는가?
- [ ] 3. **절대 금기 사항(불변 규칙) 정의**: 시스템이 절대 허용하지 않을 상태(예: 잔고 음수, 중복 발송 등)를 명시했는가?
- [ ] 4. **의존성 최소화 (1목적 1도구)**: 불필요한 서드파티 라이브러리 도입을 배제하고 표준 기술 스택을 확정했는가?
- **진입 게이트 (Pass 조건)**: UI나 코드 없이, 순수한 입력 ➔ 처리 ➔ 출력 흐름이 텍스트로 명확히 정의되었는가?

---

### [Phase 1. 골격(Skeleton) 세우기 — 데이터 모델 및 스키마]
*뼈대가 비틀리면 장기를 얹을 수 없습니다. 데이터의 틀과 상태를 정의하는 단계입니다.*

- [ ] 5. **도메인 상태(State) 정의**: 시스템이 가질 수 있는 모든 상태를 유한 상태(Enum/Const)로 정의했는가?
- [ ] 6. **데이터 스키마 및 DTO 수립**: DB 테이블 구조, 전송 객체, 필드 타입(정수, 문자열, Nullable)을 엄격히 선언했는가?
- [ ] 7. **상태 전이(State Transition) 규칙 수립**: 임의 건너뛰기 없이 허용된 경로로만 상태가 변경되도록 규칙을 세웠는가?
- [ ] 8. **불변 식별자 확정**: ID, 생성 시각 등 절대 변경되어서는 안 될 식별 필드를 동결했는가?
- **진입 게이트 (Pass 조건)**: 스키마와 데이터 모델만 보고도 시스템 전체의 데이터 흐름이 읽히는가?

---

### [Phase 2. 면역계(Immunity) 선구축 — 핀테스트(Pin-Test) 선작성]
*몸을 만들기 전에 자가진단 항체와 안전망을 먼저 준비합니다. (Red 선행)*

- [ ] 9. **실패하는 단위 핀테스트 선작성 (Red)**: 핵심 비즈니스 로직에 대해 실패하는 테스트를 먼저 작성했는가?
- [ ] 10. **독소/경계값 테스트 포함**: 0, 음수, null, 빈 문자열, 최대 한도 초과값 주입 시 방어 여부 테스트를 선작성했는가?
- [ ] 11. **객체 전체 일치(Full-Assertion) 단언**: 특정 필드만 확인하지 않고 반환 객체 전체의 동치성을 엄격히 대조했는가?
- **진입 게이트 (Pass 조건)**: 테스트 러너 실행 시 구현 코드 부재로 인해 정상적으로 Red(실패)가 뜨는 것을 확인했는가?

---

### [Phase 3. 심장(Heart) 박동 — 순수 연산(Core) 구현]
*외부 환경과 단절된 채 순수한 연산만 수행하는 무결한 심장을 만듭니다. (Green 달성)*

- [ ] 12. **순수 함수(Pure Function) 구현**: DB, 네트워크, 파일 I/O, 현재시간, 랜덤 호출이 전무한 100% 순수 함수로 비즈니스 로직을 구현했는가?
- [ ] 13. **입력 불신 및 가드 조항(Guard Clause)**: 함수 진입부에서 이상 입력 발견 시 즉시 거절(Early Return)하여 오염을 차단했는가?
- [ ] 14. **핀테스트 100% 통과 (Green)**: Phase 2에서 선작성한 테스트가 수정 없이 100% 통과되었는가?
- **진입 게이트 (Pass 조건)**: 인터넷 랜선을 뽑고 DB가 다운되어도 이 계산 모듈은 독립적으로 완벽히 동작하는가?

---

### [Phase 4. 혈관(Vessel) 연결 — 외부 I/O 및 통신(Shell) 구현]
*심장에 깨끗한 피를 공급하고 노폐물을 회수하는 외부 연결망을 뚫습니다.*

- [ ] 15. **DB 트랜잭션 및 저장소 연결**: Core 계산 결과를 영구 저장소에 원자적(Atomic)으로 기록/조회하는 함수를 작성했는가?
- [ ] 16. **외부 통신 게이트웨이 및 타임아웃**: 타사 API나 네트워크 통신 시 타임아웃 및 재시도 한계치를 필수 설정했는가?
- [ ] 17. **하드코딩 0% 방역**: DB 접속 주소, 비밀키, 고정 경로를 코드에서 완전 분리하여 환경설정(`.env`/Config)으로 추출했는가?
- [ ] 18. **입력 필터(Input Sanitizer)**: 외부 세계에서 유입된 원시 데이터가 Shell 계층을 지날 때 정화·검증을 거치게 했는가?
- **진입 게이트 (Pass 조건)**: 외부 통신이 차단되거나 DB 오류가 발생해도 시스템이 크래시 없이 안전한 예외를 반환하는가?

---

### [Phase 5. 신경망(Nerves) 통합 — 전체 흐름 제어(Orchestration)]
*장기와 혈관을 뇌(Entry Point)에 연결하여 유기적인 동작을 조율합니다.*

- [ ] 19. **단일 조율자(Flow Controller) 구현**: `Shell(수집) ➔ Core(순수연산) ➔ Shell(반영)`의 단방향 데이터 흐름을 연결했는가?
- [ ] 20. **트랜잭션 롤백 및 자원 정리**: 중간 단계 실패 시 안전한 롤백과 DB 커넥션/파일 핸들 반환을 보장했는가?
- [ ] 21. **중복 실행 방지(멱등성)**: 동일 요청이 여러 번 인입되어도 중복 처리되지 않도록 잠금 또는 식별자 검증을 거쳤는가?
- [ ] 22. **단일 로깅 체계 수립**: 모든 상태 전이와 실패 정황을 역추적할 수 있는 파일/콘솔 로그를 남겼는가?
- **진입 게이트 (Pass 조건)**: 터미널 환경에서 단 하나의 명령어로 전체 비즈니스 시나리오가 끊김 없이 끝까지 완주되는가?

---

### [Phase 6. 외피(Skin) 및 의복 — UI / 프레젠테이션 구축]
*단단한 신체 위에 사용자가 직관적으로 보고 만질 수 있는 인터페이스를 형성합니다.*

- [ ] 23. **시각적 계층 구조 수립**: 중요도에 따른 정보 배치와 일관된 디자인 토큰(컬러, 폰트, 여백)을 적용했는가?
- [ ] 24. **실시간 상태 피드백**: 로딩 중, 작업 성공, 에러, 버튼 비활성화 상태가 명확히 사용자에게 전달되는가?
- [ ] 25. **방어적 UI(클라이언트 가드)**: 폼 입력값 사전 검증 및 광클 방지(디바운스/버튼 비활성화) 처리를 적용했는가?
- [ ] 26. **300줄 한도 준수 (SRP)**: UI 뷰 및 컴포넌트 코드가 300줄을 넘지 않도록 서브 모듈로 분리했는가?
- **진입 게이트 (Pass 조건)**: 사용자가 버튼을 난타하거나 잘못된 값을 입력해도 백엔드 뇌/심장에 이상 상태가 전파되지 않는가?

---

### [Phase 7. 종합 건강검진 — 종합 검증(Verification)]
*완성된 신체를 극한 환경에 노출시켜 숨어있는 누수가 없는지 최종 점검합니다.*

- [ ] 27. **정상 시나리오 엔드투엔드 완주**: 사용자 조작부터 데이터 영구 저장까지 전체 흐름이 기대대로 완결되는가?
- [ ] 28. **장애 주입 스트레스 테스트**: 네트워크 강제 단절, 프로세스 강제 재시작 시 데이터 손실이나 상태 꼬임이 없는가?
- [ ] 29. **자원 누수(Leak) 점검**: 메모리 누수, 열려있는 커넥션 풀, 잔존 임시 파일이 없는지 확인했는가?
- [ ] 30. **전체 핀테스트 회귀 검증**: 기존 및 신규 핀테스트 전체가 100% Pass(Green) 상태를 유지하는가?
- **진입 게이트 (Pass 조건)**: 비정상 데이터 및 장애 주입에도 시스템이 다운되지 않고 복원력을 유지하는가?

---

### [Phase 8. 출산 및 유지 — 배포 및 모니터링 체계 가동]
*완성된 생명체를 운영 환경에 배치하고 생애주기를 관리합니다.*

- [ ] 31. **운영 환경변수 최종 검증**: 개발용 임시 플래그나 테스트 DB 주소가 운영 설정에 혼입되지 않았는가?
- [ ] 32. **프로세스 관리 및 자동 복구**: 프로세스 크래시 시 무중단 자동 재기동 체계를 갖추었는가?
- [ ] 33. **이상 징후 알림망 점검**: 시스템 장애나 임계치 초과 발생 시 운영자에게 실시간 경보가 전송되는가?
- [ ] 34. **클린 베이스라인 확정**: 작업 완료본의 Git 태그 지정 및 작업 트리 완전 정리(Clean)를 마쳤는가?
- [ ] 35. **Vercel + Supabase 연동 헌법 검증**: `docs/boilerplates/VERCEL_SUPABASE_연동_헌법.md` 7대 지뢰(icn1 서울 리전, 6543 트랜잭션 풀러, pg8000 풀링 헬스체크, master+태그 동시 푸시, 크롬 비번 침투 방어) 체크리스트를 100% 전수 통과했는가?

---

### [실전 퀵 트래커]
작업 진행 시 현재 위치를 아래 체크박스로 추적하며 전진하십시오:

```text
[ ] Phase 0. DNA 기획     (I/O 규격 및 금기사항 확정)
[ ] Phase 1. 골격 수립    (데이터 스키마 및 상태머신)
[ ] Phase 2. 면역 선구축  (실패하는 핀테스트 선작성 - Red)
[ ] Phase 3. 심장 연산    (Zero Side-Effect Core 작성 - Green)
[ ] Phase 4. 혈관 연결    (외부 I/O, DB, API 핸들러)
[ ] Phase 5. 신경 조율    (main 흐름 연결, 멱등성, 로깅)
[ ] Phase 6. 피부 입히기  (UI/UX, 폼 검증, 상태 피드백)
[ ] Phase 7. 종합 검진    (장애 주입, 회귀 검증 Pass)
[ ] Phase 8. 실전 배포    (환경변수 검증, 모니터링 활성화)
```
