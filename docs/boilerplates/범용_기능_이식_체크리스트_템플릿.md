# [보일러플레이트] 전천후 만능 기능 이식 & 오픈소스 흡수 표준 프레임워크
# Universal Feature Transplant & Anti-Corruption Checklist

본 체크리스트는 **GitHub 오픈소스, 외부 라이브러리, 기존 레거시 코드, 타 업체(테넌트) 기능**을 내 시스템(웹, 모바일 앱, 윈도우 데스크톱 C#/Python/Qt 등)으로 가져올 때, **시스템 오염과 런타임 충돌을 100% 방지하고 무결점으로 이식하기 위한 Google 시니어급 아키텍처 실전 체크리스트**입니다.

위에서부터 1번~15번까지 순서대로 체크박스를 채우며 진행합니다.

---

### [Phase 1. 의존성 방역 및 환경 격리 (Dependency Quarantine)]
*외부 코드의 지저분한 환경이 내 메인 프로젝트를 오염시키지 않도록 원천 차단하는 단계입니다.*

- [ ] 1. **외부 라이브러리 최소화 & 대체**: 오픈소스의 불필요한 대형 패키지를 내장 라이브러리(Standard Library)나 프로젝트 표준 라이브러리로 대체/격리했는가?
- [ ] 2. **하드코딩 절대 방역**: 오픈소스에 박혀있는 특정 OS 절대 경로(`C:\Users\...`), 고정 IP, 특정 포트, 매직 넘버를 찾아내어 `config.ini` / `.env` / 파라미터로 100% 추출했는가?
- [ ] 3. **OS 권한 및 파일 I/O Fallback**: 윈도우 파일 쓰기 금지(`PermissionError`)나 경로 미존재 상황을 대비해 안전한 폴더(바탕화면, Temp) Fallback 처리를 설계했는가?

---

### [Phase 2. 순수 비즈니스 Core 발라내기 (Pure Function Extraction)]
*화면, 네트워크, 데이터베이스 I/O 찌꺼기를 싹 걷어내고 순수 계산 로직만 칼로 발라내는 단계입니다.*

- [ ] 4. **알맹이(Pure Core) 분리**: 계산, 파싱, 판정, 데이터 정제 로직을 DB/네트워크/시간/랜덤 호출이 전혀 없는 **100% 순수 함수(Pure Function)**로 추출했는가? (`src/.../core/` 분리)
- [ ] 5. **부패 방지 계층 (Anti-Corruption Layer / 어댑터)**: 외부 소스가 내뱉는 제멋대로의 출력값을 내 시스템 표준 데이터 규격(표준 Dict, List, JSON)으로 1:1 변환해주는 단 하나의 변환기(Adapter)를 거치게 했는가?
- [ ] 6. **전역 변수(Global State) 0% 박멸**: 오픈소스 내부의 `global` 키워드나 모듈 레벨 상태 변수를 모조리 제거하고 함수의 인자(Input)와 반환값(Output)으로만 흐르게 만들었는가?

---

### [Phase 3. 런타임 & 스레드 비동기 격리 (Execution Shell Isolation)]
*윈도우 창 멈춤(Freezing)이나 웹 요청 블로킹을 차단하는 실행 껍데기 분리 단계입니다.*

- [ ] 7. **UI 응답 없음(Freezing) 원천 차단**: 수집, 계산, 대용량 I/O 등 무거운 연산이 메인 UI 스레드에서 직접 돌지 않고 **백그라운드 Worker 스레드 / 로컬 경량 프로세스**로 완벽 격리되었는가?
- [ ] 8. **통신 프로토콜 표준화**: 웹/앱 브라우저와 통신할 때 Private Network Access(PNA), CORS 헤더 및 비동기 Fetch/소켓 인터페이스가 규격대로 열려있는가?
- [ ] 9. **1회성 원클릭 실행/등록 패키징**: 고객사나 사용자가 복잡한 설치 없이 바로 켤 수 있는 단일 실행 스크립트(`.bat`, 커스텀 URL 프로토콜)가 준비되었는가?

---

### [Phase 4. UI 바인딩 & 상태 충돌 방어 (State & Mutation Defense)]
*사용자가 화면을 조작할 때 발생하는 글자 덮어쓰기, 롤백, 데이터 뒤섞임 버그를 차단하는 단계입니다.*

- [ ] 10. **기본값 부활(롤백) 방어**: 사용자가 입력 폼을 모두 비우거나 삭제하고 저장했을 때, 과거 기본값이 강제로 되살아나는 버그가 차단되었는가?
- [ ] 11. **타이핑 중 리셋 방어**: 5초/10초 폴링 타이머나 백그라운드 상태 갱신이 일어날 때, 사용자가 한창 입력 중인 폼이 초기화되지 않도록 로딩 플래그(`isConfigLoaded`)로 잠궜는가?
- [ ] 12. **300줄 한도 엄수 (SRP)**: UI 뷰 파일이나 진입점 코드가 300줄을 초과하지 않고 책임별로 깔끔하게 분리되었는가?

---

### [Phase 5. 정렬 보존 & 입출력 동치성 검증 (Equivalence Verification)]
*화면의 표시 순서와 파일 다운로드 결과가 1:1로 일치하는지 최종 검증하는 단계입니다.*

- [ ] 13. **사용자 등록 순서(Index) 보존**: 기계적 가나다순으로 제품/항목이 멋대로 섞이지 않고, 사용자가 등록/원하는 순서대로 1번 묶음 ➔ 2번 묶음이 엄격히 유지되는가?
- [ ] 14. **그룹별 완전 격리 + 핵심 기준 우선순위**: 다른 그룹의 항목이 중간에 끼어들지 않고, 각 그룹 안에서만 핵심 기준(위반 최상단, 최저가순 등)대로 정확히 2중 정렬되는가?
- [ ] 15. **화면과 다운로드 데이터 1:1 완벽 일치**: 웹/앱 화면에 렌더링된 행(Row) 순서와 엑셀/CSV/PDF 다운로드 파일의 행 순서가 토씨 하나 안 틀리고 정확히 일치하는지 대조 확인했는가?
