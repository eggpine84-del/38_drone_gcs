# 범용 프로젝트 아키텍처 및 폴더 구조 표준 (Universal Blueprint)

> **핵심 설계 철학 (Three-Tier Architecture: Engine ➔ Features ➔ Shared)**:
> 1. **시스템 척추 엔진 (Engine)**: 시스템 핵심 헌법(핵심 상태머신, 불변 감사 원장, 비즈니스 가드 등)을 100% 장악하는 **'시스템의 단일 공급원(SSOT) 척추'**입니다. (절대 피처 단위로 쪼개지 않음)
> 2. **수직 피처 (Features)**: 대시보드, 주문/결제, 알림, 검색 등 모든 비즈니스 업무가 **'독립된 수직 폴더'**로 완결됩니다. (피처 간 상호 직접 참조 영구 금지)
> 3. **순수 공유함 (Shared)**: 도메인을 전혀 모르는 순수 범용 유틸리티(날짜, 수학, 로거)로, **최소 3개 피처 이상 중복 필요 시에만 선택적 생성**합니다 (Rule of Three).

## 2. 3대 도메인별 범용 적용 방식 (Universal Use-Cases)

이 폴더 구조는 코드 재설계 없이 오직 `src/features/`의 부품 교체만으로 모든 도메인을 수용합니다:

### A. 일반 웹 서비스 / 비즈니스 플랫폼 대시보드
* **척추 엔진(`src/engine/`)**: `src/engine/shell/db_adapter.py` (SQLite 원장 보존), `core/` (핵심 상태머신)
* **피처(`src/features/`)**:
  * `features/auth/`: 사용자/관리자 인증 및 세션 가드 (독립 피처로 편입)
  * `features/orders/`: 주문 처리 (`core/state_machine.py`, `shell/routes.py`, `templates/`)
  * `features/settlement/`: 엑셀 정산 (`core/calculator.py`, `shell/excel_io.py`)

### B. AI 임베딩 & RAG 검색 시스템 (Vector Search)
* **척추 엔진(`src/engine/`)**: 
  * `data/vector_db/`: 로컬/원격 벡터 인덱스 저장소
  * `src/engine/shell/vector_adapter.py`: ChromaDB/FAISS 단일 연결 인프라
* **피처(`src/features/`)**:
  * `features/document_embed/`: 
    * `core/chunker.py`: 텍스트 청크 분할 및 토큰 오버랩 순수 계산 (외부 I/O 0건)
    * `shell/embed_worker.py`: OpenAI/Ollama API 호출 후 벡터 저장소 적재
  * `features/semantic_search/`:
    * `core/similarity.py`: 코사인 유사도 점수 랭킹 및 필터링 순수 알고리즘
    * `shell/search_routes.py`: 검색 API 엔드포인트 및 RAG 컨텍스트 생성

### C. 모바일 앱 / Headless API 백엔드 (Flutter, React Native)
* **척추 엔진(`src/engine/`)**: 동일한 `src/engine/` 척추 그대로 유지
* **피처(`src/features/`)**:
  * `templates/` 대신 `shell/routes.py`에서 표준 단일 봉투(`{"success": True, "data": ...}`) JSON만 반환
  * 클라이언트가 웹 브라우저에서 모바일 앱으로 변경되어도 백엔드 코어는 0줄 수정

## 3. 엔지니어링 5대 절대 헌법 (Hard Rules)

1. **의존성 일방통행 및 피처 간 횡적 참조 영구 금지 (No Cross-Feature Import)**:
   * `features/`는 하향으로 `engine/`을 참조할 수 있으나, 피처끼리는 서로를 절대 직접 `import`할 수 없습니다.
   * `engine/`은 상향인 `features/`를 절대 알지 못합니다 (하향 의존 역류 영구 금지).
2. **시스템 척추 엔진(`engine/`)의 독점 통제**:
   * 시스템 핵심 헌법(상태머신, 불변 감사 원장, 비즈니스 가드, DB 어댑터)은 각 피처에 분산시키지 않고 중앙 척추(`src/engine/`)가 100% 독점 통제합니다.
3. **순수 공유함(`shared/`) 생성 판정 기준**:
   * "완전히 다른 성격의 프로젝트에 그대로 복사해도 동작하는 도메인 무관 순수 도구인가?"가 Yes이고 최소 3개 피처 이상 중복될 때만 생성합니다 (Rule of Three).
4. **Core-Shell 물리 격리 준수**:
   * 모든 피처 내부의 `core/`는 DB, 네트워크, 파일, 시스템 시간 조회를 절대 포함하지 않는 순수 함수(Pure Function)로만 작성합니다.
5. **폐기 비용 0% (Clean Teardown)**:
   * 특정 기능의 서비스가 종료되면, `src/features/{기능명}/` 폴더를 통째로 삭제하고 `main.py`의 라우터 등록 1줄만 지우면 시스템 전체에 부작용(Side-effect) 0건으로 완전 제거됩니다.
