# [신규 프로젝트 이관 및 인프라 격리 실전 매뉴얼]
# (Project Migration & Infrastructure Isolation Runbook)

> **목적**: 기존 프로젝트(예: `32_smtrade`)에서 코드를 복사해 새로운 번호(예: `33`, `34`...)의 보일러플레이트나 신규 서비스를 구축할 때, **DB 오염·Git 충돌·환경변수 누락 없이 10분 만에 상용 배포까지 완수**하는 실전 체크리스트.

---

## 1. 반드시 알아야 할 5대 실전 지뢰

1. **DB 겹침 참사**: 복사해 온 `config/.env`에 이전 프로젝트의 `DATABASE_URL`이 남아있어, 새 프로젝트를 실행하는 순간 **이전 프로젝트의 운영 DB가 덮어써지는 사고**.
2. **Supabase 무료 2개 한도**: Supabase 무료 플랜은 계정 전체에서 **활성 프로젝트 최대 2개**로 제한됨 (새 프로젝트를 무한정 생성 불가).
3. **스키마 충돌 (기존 프로젝트 재활용 시)**: 기존 DB에 남아있던 예전 테이블(학생, 교사, 판매자 등)이나 상이한 `users` 컬럼(`user_id` vs `id`, `email` vs `username`) 때문에 새 프로젝트 실행 시 컬럼 미존재 에러 발생.
4. **Supabase 5432 vs 6543 포트 지뢰**:
   - `5432 (Direct)`: 최신 Supabase는 IPv6 전용이라 일반 PC/Vercel 서버리스에서 **Connection Timeout** 발생!
   - `6543 (Transaction Pooler)`: 반드시 풀러 주소(`aws-0` 또는 `aws-1` 리전)를 사용해야 함.
   - 비밀번호에 `#` 등 특수문자가 있을 경우 URI 인코딩(`%23`) 필수!
5. **Vercel 환경변수 미주입 배포**: `.gitignore`로 인해 `.env`는 깃허브에 안 올라가므로, Vercel 콘솔에서 수동으로 환경변수를 넣고 **반드시 Redeploy**를 눌러야 정상 동작함.

## 2. 실전 원터치 5단계 이관 순서

### 1단계: 로컬 복사 직후 이전 DB 연결 원천 차단
새 폴더를 만들고 코드를 복사한 즉시 가장 먼저 수행해야 합니다:

1. **`config/.env` 점검**:
   - 이전 프로젝트의 `DATABASE_URL`을 즉시 비우거나 새 프로젝트 전용 URL로 교체
2. **로컬 SQLite DB 파일명 범용화**:
   - `src/shared/shell/db_adapter.py` 내 `PROD_DB_PATH` 확인:
     `data/db/smtrade.db` ➔ `data/db/dashboard.db`로 프로젝트에 맞게 변경

---

### 2단계: Supabase 프로젝트 확보 및 100% 클린 리셋
무료 2개 한도로 인해 기존 프로젝트를 재활용하거나 새 프로젝트를 연결할 때:

1. **정확한 Transaction Pooler (6543 포트) URI 추출**:
   - Supabase 콘솔 상단 **`Connect`** 버튼 클릭
   - **Type**: `Transaction pooler` (Port 6543) 선택
   - **Method**: `URI` 선택 후 복사
   - 비밀번호 내 특수문자 `#`는 `%23`으로 변환:
     `postgresql://postgres.<REF>:<인코딩된비번>@aws-1-ap-northeast-2.pooler.supabase.com:6543/postgres`
2. **과거 잔여 스키마 클린 리셋 (보일러플레이트 순수성 확립)**:
   - 과거 다른 프로젝트의 테이블들이 섞여 있다면 아래 파이썬 스크립트 1회 실행으로 백지 초기화:
   ```python
   # scratch/reset_db.py
   from src.shared.shell.db_adapter import get_db_connection
   from src.shared.shell.db_schema import init_db
   from src.auth.shell.auth_repository import seed_master_user_if_empty

   conn = get_db_connection()
   cur = conn.cursor()
   cur.execute("SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' AND table_type = 'BASE TABLE';")
   for t in [r[0] for r in cur.fetchall()]:
       cur.execute(f'DROP TABLE IF EXISTS public."{t}" CASCADE;')
   conn.commit()
   conn.close()

   # 새 프로젝트 표준 5대 테이블 및 관리자 계정 생성
   init_db()
   seed_master_user_if_empty(master_username="관리자이메일", master_password="비번")
   ```

### 3단계: Git 초기화 및 깃허브 원격 저장소 바인딩
새 폴더는 `.git`이 없으므로 새로 연결해야 합니다:

1. **깃허브(github.com)에서 빈 새 레포지토리 생성**
2. **로컬 터미널에서 초기화 및 커밋**:
   ```bash
   git init
   git add -A
   git commit -m "feat: 새 프로젝트 최초 베이스라인 확정"
   ```
3. **원격 저장소 바인딩 및 태그 푸시**:
   ```bash
   git remote add origin https://github.com/계정명/새레포지토리이름.git
   git push -u origin master
   ```

### 5단계: Vercel 상용 배포 및 환경변수 주입

1. **Vercel 콘솔(`vercel.com`) 접속**:
   - `Add New...` ➔ `Project` ➔ 신규 깃허브 레포지토리 `Import`
2. **`Settings` ➔ `Environment Variables`에 3대 핵심 키 주입**:
   - `DATABASE_URL`: Supabase 6543 풀러 URI
   - `MASTER_USERNAME`: 관리자 로그인 아이디 (예: `eggpine84@gmail.com`)
   - `MASTER_INITIAL_PASSWORD`: 관리자 초기 비밀번호 (예: `6300`)
3. **재배포 (Redeploy)**:
   - `Deployments` 탭 ➔ 최신 배포 우측 점 3개(`...`) ➔ **`Redeploy`** 클릭
4. **상용 Production 도메인 접속 확인**:
   - `https://<프로젝트명>.vercel.app/login` 접속
   - 등록한 관리자 계정으로 로그인 성공 확인 ➔ **구축 완료!**

### 6단계: 이관 완료 후 신규 기능(메뉴) 개발 헌법 (수직 슬라이스)
인프라 구축 완료 후 새로운 비즈니스 기능(메뉴)을 추가할 때는 반드시 아래 **수직 슬라이스(Vertical Slice)** 표준을 100% 준수합니다:

1. **1메뉴 1슬라이스 독립 완제품 (Vertical Slice)**:
   - 메뉴 1개당 전용 폴더 2곳만 생성:
     - `src/features/[피처명]/`: `core/`(순수연산) + `shell/`(FastAPI 라우터, DB 리포지토리, HTMX 템플릿)
     - `tests/test_features/[피처명]/`: 1:1 짝꿍 핀테스트(`test_[피처명]_core.py`, `test_[피처명]_shell.py`)
   - **피처 간 직접 참조 영구 금지**: 타 피처 코드 import 불가. 공통 로직은 오직 `src/shared/`만 참조.
2. **황금 견본 복제 공식 (Zero to Hero)**:
   - 백지에서 새로 짜지 말고, 완제품인 `src/features/sample_crud/`와 `tests/test_features/sample_crud/`를 그대로 복사하여 이름과 필드만 교체.
3. **선행 핀-테스트 필수 (Pin-Test First & Red-First)**:
   - 비즈니스 코드 작성 전 `tests/test_features/[피처명]/` 테스트 선작성 및 실패(Red) 증명 필수. 통과(Green) 후 커밋.
4. **시스템 등록 2곳 (단 1줄씩)**:
   - `main.py`: `app.include_router(피처_router)` 등록.
   - `menus` DB: `db_schema.py` 또는 DB `menus` 테이블에 1줄 등록 (사이드바 자동 렌더링).
   - 상세 10분 추가 절차: `docs/guides/신규_메뉴_추가_가이드.md` 참조.

### 7단계: [원터치] 홈 화면(대시보드) 커스텀 교체 3초 공식
고객사별 맞춤형 그리드/홈 화면 요구 시 기존 대시보드를 뜯지 않고 100% 독립 교체:
1. **피처 생성**: `src/features/[홈피처명]/`에 전용 템플릿·라우터 작성 (고객 맞춤 그리드 자유 구성)
2. **루트('/') 인계**: `main.py`에서 기존 대시보드 라우터 대신 `app.include_router(신규홈_router)` 등록
3. **명칭 동기화**: 웹 환경설정 > 메뉴 관리에서 '종합 대시보드'의 이름/아이콘을 신규 홈 명칭으로 변경
